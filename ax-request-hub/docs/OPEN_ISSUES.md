## OI-001: SQLite → PostgreSQL 전환 (P3-4)

**상태:** 🔴 미완료  
**우선순위:** 높음 (전사 배포 전 필수)  
**출처:** 검토보고 P3-4

### 문제

현재 `SQLite(ax_hub.db)`를 단일 파일 DB로 사용 중이다. 다음 한계로 인해 전사 배포 시 운영 불가:

| 한계 | 영향 |
|------|------|
| 쓰기 동시성 없음 (Writer Lock) | 다수 직원 동시 신청 시 쓰기 지연·실패 |
| 다중 인스턴스 공유 불가 | 로드밸런서 또는 PM2 클러스터 구성 불가 |
| 자동 백업·복제 없음 | 파일 손상 시 데이터 전체 유실 위험 |
| 스토리지 한계 | 대용량 감사 로그 누적 시 성능 저하 |

### 권고 전환 방안

1. **대상 DB:** PostgreSQL 14 이상 (또는 회사 표준 DB 정책에 따름)
2. **전환 절차:**
   - Prisma `schema.prisma`의 `provider = "sqlite"` → `"postgresql"` 변경
   - `npx prisma migrate deploy`로 스키마 적용
   - 기존 데이터 마이그레이션 스크립트 작성 및 검증
   - 연결 문자열 환경변수 교체 (`DATABASE_URL`)
3. **예상 공수:** 3~5일 (마이그레이션 검증 포함)
4. **전환 전 주의:** JSON 직렬화 필드(`messages`, `relatedDocs`, `targetUsers` 등)를 `@db.Text` 유지 또는 `Json` 타입으로 교체 검토 필요

## OI-002: 감사 로그 보존기간·위변조 방지 명세 (P3-4)

**상태:** 🔴 미완료  
**우선순위:** 높음 (금융회사 법규 요건)  
**출처:** 검토보고 P3-4

### 문제

현재 `AuditLog` 모델은 단순 기록 모델로, 다음이 미정의:

- **보존 기간:** 전자금융감독규정 제34조에 따라 전자금융거래 기록은 **최소 5년** 보존 의무. AX Hub AI 과제·에이전트 결정 기록이 이 범위에 해당하는지 법무 확인 필요.
- **위변조 방지:** 현재 `AuditLog` 레코드는 DB에서 직접 수정·삭제 가능. 변조 불가 원칙 미구현.
- **로그 범위:** 어떤 이벤트를 반드시 감사 로그로 남겨야 하는지 목록 미정의.

### 권고 조치

1. **법무 검토:** AI 과제 승인·에이전트 활성화 기록의 전자금융감독규정 적용 여부 확인
2. **보존 기간 설정:** `AuditLog`에 `retainUntil DateTime` 필드 추가, 자동 삭제 방지
3. **위변조 방지 방안 (우선순위순):**
   - (단기) DB 사용자 권한으로 `AuditLog` 테이블 DELETE/UPDATE 차단
   - (중기) 해시 체인(이전 로그 해시 포함) 방식 도입
   - (장기) 별도 불변 로그 스토리지(예: AWS CloudWatch Logs, Loki) 연동
4. **필수 감사 이벤트 목록 정의:** 과제 승인/반려, 에이전트 상태 변경, 레벨 부여, 역할 변경, 토큰 초과 등

## OI-003: 시크릿 관리 체계 (P3-4)

**상태:** 🟡 개발 환경 임시 처리  
**우선순위:** 중간 (사내 배포 전 필수)  
**출처:** 검토보고 P3-4

### 문제

현재 다음 시크릿이 `.env` 파일로 로컬에만 관리되고 있다:

| 시크릿 | 현황 | 위험 |
|--------|------|------|
| `NEXTAUTH_SECRET` | .env 평문 | 버전 관리에 포함 시 유출 위험 |
| `ANTHROPIC_API_KEY` | .env 평문 | Claude API 과금 노출 |
| `DATABASE_URL` | .env 평문 | DB 접근 정보 노출 |

### 권고 조치

**단기 (즉시 적용 가능):**
- `.gitignore`에 `.env`, `.env.local`, `.env.production` 포함 확인
- `.env.example` 파일에 키 이름만 노출하여 신규 개발자 가이드 제공

**중기 (사내 배포 시):**
1. 회사 표준 비밀 관리 시스템 사용 (HashiCorp Vault, AWS Secrets Manager, 또는 사내 KMS)
2. 시크릿을 환경변수로 런타임 주입 (Docker/K8s Secret 또는 PM2 env)
3. `ANTHROPIC_API_KEY` 로테이션 주기 수립 (분기 1회 권고)

**운영 체크리스트:**
- [ ] `.env` 파일이 Git 이력에 포함되지 않음 확인 (`git log --all -S "ANTHROPIC"`)
- [ ] API 키 최소 권한 원칙 적용 (Anthropic Console에서 사용량 알림 설정)
- [ ] 인원 퇴직 시 키 즉시 교체 절차 수립

## OI-004: KPI '3개월 60% 미달' 자동 판정 로직 실행 주체 (P3-4)

**상태:** 🔴 미완료  
**우선순위:** 중간 (운영 안정성)  
**출처:** 검토보고 P3-4

### 문제

시스템 플로우도(§2)에 "KPI 3개월 60% 미달 → RETIRE_CANDIDATE" 전환이 명시되어 있으나, 이를 실행하는 주체가 없음:

- `Agent.kpiMissCount`, `Agent.performanceFlag` 필드가 존재하나 자동 갱신 로직 미구현
- 현재는 AX팀이 `/admin/agents/[id]/kpi-record` POST로 수동 입력 후 수동으로 flag 검토

### 권고 조치

**옵션 A — 배치 스케줄러 (권장):**
1. Next.js Route Handler + Vercel Cron Job (또는 사내 cron)으로 월말 자동 실행
2. 실행 내용:
   - `AgentKpiRecord` 최근 3개월 조회
   - 달성률(`achieveRate`) 평균 < 60% 에이전트 → `performanceFlag = RETIRE_CANDIDATE`
   - AX팀 이메일 알림 발송
3. 실행 엔드포인트: `POST /api/admin/agents/kpi-check` (신규 생성 필요, AX팀 전용)

**옵션 B — 수동 판정 유지 + 대시보드 경고:**
- KPI 입력 시 `achieveRate` 누적 계산 후 `performanceFlag` 자동 갱신 (입력 시점 한정)
- 수동이지만 입력할 때마다 실시간 반영

**결정 필요:** 옵션 A vs B 중 택일 후 구현. 옵션 A는 cron 인프라 필요.

## OI-005: 이의제기 SLA 미정의 (P3-4)

**상태:** 🟡 API 구현 완료, SLA 미명세  
**우선순위:** 낮음 (운영 정책)  
**출처:** 검토보고 P3-4

### 문제

`/api/projects/[id]/appeal` POST로 이의제기 신청 API는 구현되었으나(`ProjectAppeal` 모델), 다음이 미정의:

- **처리 기한(SLA):** AX팀이 이의제기를 몇 영업일 이내에 처리해야 하는지 미명세
- **에스컬레이션 경로:** SLA 초과 시 누가 개입하는지 미정의
- **결과 통보 방식:** 신청자에게 처리 결과를 어떻게 통보하는지 미구현 (이메일 미발송)

### 권고 조치

1. **SLA 정의:** 이의제기 접수 후 **5 영업일** 이내 처리 (AX_Hub 검토보고 기준 제안)
2. **에스컬레이션:** SLA 초과 시 AX팀장에게 자동 알림 (또는 수동 에스컬레이션)
3. **결과 통보:** `ProjectAppeal.status` 변경 시 신청자 이메일 발송 (`sendApprovalEmail` 패턴 참조)
4. **거버넌스 문서 반영:** `AX-REGULATION-2026-001_AI운영규정.md`에 이의제기 SLA 조항 추가 필요
