# AX팀 AI 개발·배포 플로우 추가 조항

> 기존 거버넌스 문서(AX-REGULATION/GUIDELINE-2026-001)에 누락된 플로우 보완.
> 본 문서는 세 가지 핵심 플로우를 규정한다.

## 1. AI 크루 개발 범위 및 AX팀 인수 기준

### 1-1. 최초 기획 단계에서의 AX팀 역할

AI 과제는 **기획 단계부터 AX팀이 주도**한다. 현업 부서가 아이디어를 제출하면 AX팀이 다음을 수행한다.

| 단계 | AX팀 역할 |
|------|-----------|
| 과제 접수 | AX Request Hub를 통한 정형 신청 수집 |
| 타당성 검토 | 6차원 스코어카드 자동 평가 (임팩트·ROI·기밀등급·난이도·준비도·전략정합성) |
| 기획 확정 | 70점 이상 + G1/G2 → 자동승인 / G3·미달 → AX팀장(인표님) 보고 |
| 개발 범위 정의 | **크루 개발 범위 명시** — 크루가 담당할 PoC 범위와 AX팀 인수 기준 사전 합의 |

> **핵심 원칙**: 과제 신청 시 "크루 개발 완료 조건"을 AX팀과 합의한 뒤 착수한다.
> 합의 없이 크루가 단독으로 범위를 결정하지 않는다.

### 1-2. AI 크루의 개발 범위

AI 크루(현업 부서 또는 개인 AI 실험 주체)는 **PoC 수준까지** 개발한다. 아래 기준을 충족하면 AX팀에 인수한다.

**크루 개발 완료 조건 (모두 충족 시 인수)**

1. 핵심 기능 동작 확인 (로컬 또는 개발환경에서 시연 가능)
2. 입력/출력 데이터 명세 문서화
3. 핵심 프롬프트·파이프라인 코드 GitHub 저장
4. 예상 사용자 수 및 트래픽 규모 추정치 제출
5. 기밀 데이터 포함 여부 명시

**크루가 하지 않는 것**

- 운영 인프라 구성 (서버·DB·CI/CD)
- 사용자 인증·접근권한 설계
- SLA·모니터링·장애대응 체계 구축
- 데이터플랫폼 공식 연동

> 이 범위를 넘어서 개발하면 AX팀 인수 시 재작업 비용이 발생한다.

### 1-3. AX팀 고도화 개발

AX팀은 크루로부터 인수 후 다음을 수행한다.

1. 코드 리뷰 및 리팩토링 (보안·성능·유지보수성)
2. 운영 인프라 구성 및 데이터플랫폼 연동
3. 접근권한·감사로그·모니터링 적용
4. 배포 의사결정 (아래 2항 참조)

## 2. 배포 환경 의사결정 기준

AX팀은 인수 완료 후 아래 기준으로 배포 환경을 결정한다.

### 결정 트리

```
[기밀 데이터 포함?]
    ├─ YES → 내부 온프레미스 배포 (사내 서버)
    └─ NO
        ├─ [기존 GPT Enterprise 사용자 대상?]
        │       ├─ YES → GPT Enterprise 배포 (ChatGPT 커스텀 GPT/플러그인)
        │       └─ NO
        │           └─ [트래픽 예측 & 확장성 필요?]
        │                   ├─ HIGH → AWS 배포 (EC2/Lambda/Bedrock)
        │                   └─ LOW  → 내부 온프레미스 배포
```

### 배포 환경별 요건 요약

| 배포 환경 | 선택 조건 | 주관 | 비고 |
|-----------|-----------|------|------|
| **GPT Enterprise** | 기밀 無 + 전사 임직원 대상 + 범용 LLM 활용 | AX팀 | ChatGPT Enterprise 라이선스 필요 |
| **AWS** | 기밀 無 + 높은 트래픽/확장 필요 + 외부 API 연동 | AX팀 + IT인프라 | 예산 품의 필요 |
| **내부 온프레미스** | 기밀 데이터 포함 OR 사내 시스템 직접 연동 | AX팀 + 데이터플랫폼 | 사내 보안정책 준수 필수 |

> **원칙**: 기밀 데이터가 1건이라도 포함되면 외부 클라우드(GPT Enterprise·AWS) 배포 금지.
> AX팀장 승인 없이 배포 환경을 변경할 수 없다.

## 3. 데이터플랫폼팀 연계 플로우

AI 서비스가 회사 데이터를 활용하는 경우 데이터플랫폼팀을 반드시 거친다.

### 3-1. 플로우

```
[크루 PoC]
    ↓ (인수 요청 + 데이터 명세 제출)
[AX팀 고도화]
    ↓ (데이터 연동 요건 정의)
[데이터플랫폼팀 협의]
    ├─ 데이터 접근 권한 검토
    ├─ 데이터 품질·신선도 확인
    └─ 공식 API/파이프라인 연결
[배포 환경 결정]
    ↓
[운영 모니터링]
```

### 3-2. 크루와 데이터플랫폼팀의 직접 연동 금지

- 크루는 **임시 CSV/엑셀 파일** 또는 **개발용 샘플 데이터**만 사용한다.
- 운영 DB·데이터레이크에 직접 접근하거나 배치 파이프라인을 연결하지 않는다.
- 운영 데이터 연동은 **AX팀이 중간에서 데이터플랫폼팀에 공식 요청**한다.

### 3-3. 데이터플랫폼팀 협의 항목

AX팀이 데이터플랫폼팀에 요청 시 명시해야 할 항목:

1. 필요 데이터 목록 및 테이블명
2. 갱신 주기 (실시간 / 일 1회 / 주 1회)
3. 기밀 등급 (공개 / 내부 / 기밀)
4. 예상 조회 건수 및 부하
5. 보존 기간 및 삭제 정책
