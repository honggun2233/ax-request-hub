## 2. 새로 확인이 필요한 것

### 2-1. "과제" 용어 — 회의 결정 취지와 재충돌 가능성

`/chat`·`/dashboard`·`/projects/new`가 전부 "AI 과제"("과제 신청", "내 과제 현황")로 통일됐습니다. 제안했던 "에이전트" 통일과 다른 방향입니다.

회의 §3에서 S1이 명확히 짚었던 우려 — "본인이 만든 에이전트를 등재하는 심의 프로세스인가, '만들어주세요' 요청인가" — 를 "과제"라는 단어가 다시 열 수 있습니다. "과제"는 "해야 할 일을 맡긴다"는 뉘앙스라 "이미 만든 걸 등록합니다"와 결이 다릅니다.

**단, 의도된 설계일 가능성도 있습니다**: 신청 단계(Project 모델, 아직 승인 전)는 "과제"로, 승인·배포 후(AgentRegistry)는 "에이전트"로 구분하는 설계라면 오히려 더 정교한 용어 체계입니다.

**확인 필요**: "과제→에이전트" 전환이 의도된 설계인지, 아니면 단순히 다른 용어가 채택된 것인지.

### 2-2. `/graph` — 레거시 확정, 정리 대상

`lib/impact-graph.ts`(신규 엔진, DP카탈로그·Registry에 통합)와 `/graph`("지식 그래프 시각화")가 별개로 공존합니다. 예전에 확인된 교훈 — "지식그래프가 hub-and-spoke 시각화라 저활용됐다, 올바른 프레이밍은 영향도 질의 엔진" — 이 정확히 재현되는 상황입니다. 진짜 가치 있는 기능(질의 엔진)이 이미 다른 화면에 더 잘 구현됐으므로, `/graph`는 정리(제거 또는 재활용) 대상입니다.

**확인 필요**: `/graph`를 제거할지, 아니면 impact-graph.ts 기반으로 재구성해 하나로 합칠지.

### 2-3. 사이드바 섹션 — 3축 프레임 기준 재편 제안

AX_TEAM이 보는 8개 섹션을 3축(에이전트·데이터·토큰) + 플랫폼 운영 기준으로 재편:

```
현재 8개 섹션                       →   3축+운영 4개 그룹
─────────────────────────────────────────────────────────
운영 현황 + 과제·에이전트            →   에이전트 거버넌스
데이터 관리                          →   데이터 거버넌스 (이미 독립적, 유지)
비용 관리 + 도구·계정                →   토큰 관리
직원·리터러시 + 스킬·문서 + 거버넌스   →   플랫폼 운영
```

8개 → 4개로 줄고, 이 대화에서 확정한 3축 거버넌스 프레임과 정확히 일치합니다.
