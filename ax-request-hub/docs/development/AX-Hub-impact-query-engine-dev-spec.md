# AX Hub — 영향도 질의 엔진 개발 스펙

**작성일**: 2026-08-21
**우선순위**: ★★★ (데이터 관리 축의 완결 조건)

---

## 1. 배경

데이터 관리 축은 기본 워크플로우(카탈로그·신청·심사·프로비저닝)는 갖춰져 있으나, "이 데이터를 회수하면 몇 개 에이전트가 영향받는가"를 답하는 영향도 질의 엔진이 없다. 이게 없으면 데이터 관리는 "판단 시스템"이 아니라 "기록 시스템"에 머문다.

---

## 2. 두 방향, 하나의 엔진

```
A. 회수 시 영향 조회 — "이 데이터를 회수하면 몇 개 에이전트가 멈추나" (데이터 → 에이전트)
B. 에이전트 의존성 조회 — "이 에이전트가 의존하는 데이터가 뭔가" (에이전트 → 데이터)
```

두 방향은 같은 그래프 탐색 엔진(다중홉 — 데이터가 참조하는 다른 데이터 → 그걸 쓰는 다른 에이전트까지)으로 구현하되, UI 노출은 분리한다.

---

## 3. 착수 순서 — A 우선

**A(회수 시 영향 조회)부터 착수한다.** 이유: A가 없을 때의 피해는 실제 운영사고(모르고 회수 → 에이전트 중단)이고, B가 없을 때의 피해는 불편함(수동으로 확인)이다. 사고 방지가 편의성보다 우선한다.

```
이번 세션: 그래프 탐색 엔진 + A(데이터→에이전트) UI, DP 화면
다음 세션: 같은 엔진 재사용 + B(에이전트→데이터) UI, AX팀 심사 화면
```

두 방향을 한 세션에 붙이지 않는다 — 범위 확장으로 세션이 늘어지는 패턴(라우팅 설계 4차 재설계 등)을 반복하지 않기 위함.

---

## 4. API 설계

```
GET /api/graph/impact?dataAssetId={id}
  → 응답: {
      directAgents: [{ agentId, agentName, status }],      // 직접 참조
      indirectAgents: [{ agentId, agentName, viaDataId }],  // 다른 데이터를 경유한 간접 참조
      totalAffected: number
    }

GET /api/graph/dependencies?agentId={id}   (다음 세션, B방향)
  → 응답: {
      directDataAssets: [{ dataAssetId, dataAssetName }],
      indirectDataAssets: [{ dataAssetId, dataAssetName, viaAgentId }]
    }
```

두 엔드포인트는 같은 내부 그래프 탐색 함수(`traverseImpactGraph(nodeId, direction)`)를 방향만 바꿔 호출한다.

---

## 5. UI 배치 — 지금 반드시 확정해야 할 것

### 문제

기존 사이드바 설계안에서 "영향도분석" 메뉴가 AX_TEAM의 "에이전트 거버넌스" 섹션에만 들어가 있고, DATA_PLATFORM의 "데이터 거버넌스" 섹션엔 없다. 지금 A방향(데이터→에이전트)을 DP 화면에 붙이기로 했는데, DP가 보는 섹션에 이 메뉴가 자리를 못 잡은 상태다.

### 수정

```
데이터 거버넌스 (DATA_PLATFORM)
  + "영향도 분석" 메뉴 신규 추가 — A방향(회수 시 영향 조회) 노출
    데이터 자산 상세 화면 또는 회수 버튼 클릭 시 "영향받는 에이전트 N개" 배지 표시

에이전트 거버넌스 (AX_TEAM)
  영향도분석 메뉴 유지 — B방향(의존성 조회)은 다음 세션에서 여기 노출
```

**개발 지시**: 그래프 탐색 엔진 구현과 동시에, DATA_PLATFORM 사이드바 섹션에 영향도분석(A방향) 메뉴를 반드시 추가할 것. 엔진만 만들고 DP 화면에 노출을 빠뜨리면 실제 사용자가 접근할 방법이 없어진다.

---

## 6. UI 동작 — 회수 버튼과의 연동

```
데이터 자산 상세 화면 → "회수" 버튼 클릭
  → 클릭 즉시 GET /api/graph/impact 호출
  → "영향받는 에이전트 3개 (그중 1개 PRODUCTION 운영중)" 배지 표시
  → 확인 모달: "정말 회수하시겠습니까? PRODUCTION 에이전트 1개가 중단됩니다" [취소] [계속]
```

기존 `revoke/route.ts`의 "연결된 PRODUCTION 에이전트 1건 자동 SUSPENDED" 로직(1:1 하드코딩)을 이 엔진 기반 다중홉 조회로 교체한다.
