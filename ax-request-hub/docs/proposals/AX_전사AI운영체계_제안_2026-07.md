## 1. 전사 AI 스킬 관리 체계

### 1.1 현황 및 문제점

현재 AI 도구(Claude 등)를 활용하는 임직원이 각자 프롬프트·지침을 개별로 관리하고 있어 아래 문제가 발생하고 있다.

- **재사용 불가**: 좋은 프롬프트·워크플로우가 개인 PC에만 존재하고 공유되지 않음
- **품질 편차**: 같은 업무를 사람마다 다른 방식으로 AI에 지시 → 결과 품질 불균일
- **관리 공백**: 기밀 데이터를 포함하는 프롬프트가 검증 없이 유통될 위험

### 1.2 제안 방향

사내 GitLab에 전용 스킬 리포지토리를 신설하고, AX Hub를 통해 전사원이 검색·활용하는 체계를 구축한다.

```
[크루 작성] → GitLab MR → [AX팀 리뷰·승인] → main 머지
                                                      │
                                             GitLab CI 자동 실행
                                                      │
                                          AX Hub 카탈로그 자동 동기화
                                                      │
                                            [전사원 조회·활용]
```

### 1.3 GitLab 리포지토리 구조

**리포명**: `samsung-am/ax-skills`

```
ax-skills/
├── catalog.yml                  ← 전체 스킬 인덱스 (CI가 자동 생성)
├── template/
│   └── SKILL_TEMPLATE.md        ← 스킬 작성 표준 템플릿
└── skills/
    ├── 업무자동화/
    │   ├── 이메일-요약.md
    │   ├── 회의록-작성.md
    │   └── 보고서-초안.md
    ├── ETF운용/
    │   ├── NAV-검증.md
    │   └── 리밸런싱-체크.md
    ├── 리서치/
    │   ├── 시장분석.md
    │   └── 공시-요약.md
    ├── 문서작성/
    │   └── 내부보고서.md
    └── 데이터분석/
        └── 포트폴리오-분석.md
```

### 1.4 스킬 파일 표준 형식

모든 스킬은 아래 헤더를 반드시 포함한다.

```markdown
---
id: skill-etf-nav-check
name: NAV 검증 스킬
version: 1.0.0
category: ETF운용
author: 홍길동 (IT업무개발팀)
approved_by: AX팀
approved_at: 2026-07-01
status: active          # active / deprecated / draft
target_users: [운용역, IT팀]
security_level: G1      # G1(일반) / G2(내부) / G3(기밀)
---

## 목적
(이 스킬이 해결하는 업무 문제)

## 사용 방법
(Claude 또는 AI 도구에 어떻게 붙여넣는지)

## 프롬프트
(실제 프롬프트 텍스트)

## 예시 입출력
(예시 1~2개)

## 주의사항
(기밀 데이터 입력 금지 등)
```

### 1.5 권한 구분

| 역할 | 권한 |
|------|------|
| 전사원 | AX Hub 카탈로그 조회·복사 (G1 스킬) |
| 해당 부서원 | G2 스킬 접근 (부서 승인 후) |
| 크루 (제안자) | GitLab MR 생성 (스킬 초안 제출) |
| AX팀 | MR 리뷰·승인·머지, 스킬 폐기 결정 |
| 정보보호팀 | G3 스킬 접근 제한·감사 |

### 1.6 AX Hub 카탈로그 연동

AX Hub에 `/skills` 탭을 추가하여 직원들이 별도 시스템 없이 조회·활용할 수 있도록 한다.

- 카테고리별 필터·검색
- 스킬 내용 미리보기
- 복사 버튼 (Claude 등에 바로 붙여넣기)
- 사용 평점·후기 (품질 자정 기능)
- GitLab CI webhook으로 자동 동기화 (수동 관리 불필요)

### 1.7 실행 일정

| 단계 | 내용 | 기간 |
|------|------|------|
| 1단계 | GitLab 리포 신설, 템플릿 작성, 초기 스킬 10종 등록 | 2주 |
| 2단계 | AX Hub `/skills` 카탈로그 탭 개발 | 2주 |
| 3단계 | GitLab CI 자동 동기화 파이프라인 구성 | 1주 |
| 4단계 | 전사 공지·사용 가이드 배포 | 1주 |

### 2.2 SSOT 원칙 (Single Source of Truth)

문서 관리의 핵심 원칙: **Markdown(.md)이 원본, Word는 보고·배포용 변환본**.

```
.md 파일 (GitLab ax-governance 리포)
    ← 수정·버전관리·리뷰 모두 여기서
    → Word 변환 (경영진 보고, 법무 검토, 공람)
    → AX Hub 문서 뷰어 (전사원 상시 접근)
```

Word 파일을 원본으로 쓰면 안 되는 이유: 버전 관리 불가, 변경 이력 추적 불가, 비교 검토 어려움.

### 2.3 추가로 필요한 문서

현재 체계에서 누락된 부분을 보완한다.

| 신설 문서 | 필요 이유 |
|-----------|-----------|
| `AX_스킬_카탈로그.md` | 전사 배포 스킬 목록·용도·호출법 (스킬 체계 수립과 연동) |
| `AX_사용자_FAQ.md` | 반복 문의 집약 → AX팀 응대 부담 감소 |
| `AX_공지이력_2026.md` | 정책 변경·신규 스킬 공지 이력 한 곳 관리 |

### 2.4 관리 체계

**저장 및 버전 관리**

```
GitLab: samsung-am/ax-governance
├── docs/                    ← 공식 문서 4종
├── supplements/             ← 보완 문서 3종
├── catalog/                 ← 스킬 카탈로그·FAQ·공지
└── CHANGELOG.md             ← 전체 문서 변경 이력
```

**개정 절차**

```
개정 필요 발생
    │
    ├─ 경미한 수정 (오타·사실 수정)
    │   → 담당자 직접 수정 → AX팀장 승인 → 반영
    │
    └─ 내용 변경 (조항 추가·삭제·정책 변경)
        → MR 생성 → AX팀 + 관련 부서 리뷰 → 부사장 승인 → 반영 → 전사 공지
```

**정기 현행화**: 분기 1회 (1·4·7·10월) 문서 현행화 점검 — 담당 AX팀.

### 2.5 사용자별 행동 지침

직원들이 "무슨 상황에서 어떤 문서를 보면 되는지"를 명확하게 안내한다.

| 상황 | 참조 문서 |
|------|-----------|
| AI 과제 신청 전 체크 | AX-REGULATION 제3조 (금지행위 확인) |
| 신청서 작성 | AX-MANUAL §2 (항목별 작성법·점수 올리는 팁) |
| 개발 착수 시 | AX_개발표준 §4 (강제 기술 스택) |
| Gate 2 통과 준비 | AX_AI개발플로우 §4 (자가점검 4항목) |
| 스킬 찾을 때 | AX_스킬_카탈로그 또는 AX Hub `/skills` |
| 정책 변경 여부 확인 | AX_공지이력 또는 CHANGELOG.md |

### 2.6 AX Hub 문서 뷰어 연동

AX Hub에 `/docs` 탭을 추가하여 GitLab MD 파일을 웹에서 바로 열람 가능하게 한다.

- 문서 목록·검색
- Markdown 렌더링 (그대로 HTML로 표시)
- 버전 이력 보기
- Word 변환 다운로드 버튼

→ 직원들은 GitLab 계정 없이도 AX Hub에서 항상 최신 문서를 볼 수 있다.

## 3. A2A 에이전트 환경 구축

### 3.1 A2A란

A2A(Agent-to-Agent)는 AI 에이전트가 다른 AI 에이전트에게 직접 작업을 위임하고 결과를 받는 통신 구조다. Google이 2025년 표준 프로토콜을 발표했으며, Anthropic의 MCP(Model Context Protocol)와 결합하는 것이 현재 업계 방향이다.

```
[기존] 사람 → AI 에이전트 → 결과
[A2A]  사람 → 오케스트레이터 에이전트
                    ├→ 컴플라이언스 에이전트
                    ├→ 데이터 분석 에이전트
                    └→ 문서 생성 에이전트 → 최종 결과
```

### 3.2 현황 (Phase 1 — 부분 구현)

현재 AX Hub에 에이전트 레지스트리(`/registry`)가 구현되어 있으며, 아래 수준까지 완성되어 있다.

- 에이전트 19종 등록 및 역할 정의
- Gate 1·2·3 라이프사이클 관리 (단계별 신뢰점수)
- 사람이 AX Hub를 통해 AI 과제를 신청하면 자동 평가·라우팅

현재 수준: **Human-to-Agent (사람이 에이전트를 호출)**

### 3.3 단계별 구축 로드맵

**Phase 1 — 현재 (2026-07 기준): Human-to-Agent 안착**

```
사용자 → AX Hub → [평가 에이전트] → 승인/반려 결과
```

- 목표: AX Hub 기반 과제 신청·자동평가 프로세스 전사 안착
- 잔여 과제: Gate 2 실질화, 운용역 리뷰 체계 완성
- 완료 기준: 월 과제 신청 10건 이상, 자동승인율 60% 이상

**Phase 2 — 2026-Q4: Agent-to-Agent 기본 레벨**

```
오케스트레이터 에이전트
    ├→ 컴플라이언스 검토 에이전트 (자동 규정 확인)
    ├→ 기술 검토 에이전트 (Gate 2 자가점검 자동화)
    └→ 문서 생성 에이전트 (승인결과 자동 문서화)
```

- 구현 요소:
  - **MCP 서버**: 에이전트가 AX Hub API, DMS, 데이터플랫폼에 접근하는 통합 게이트웨이
  - **에이전트 오케스트레이터**: 작업 분배·결과 취합 역할
  - **감사 로그**: 에이전트가 수행한 모든 작업 기록 (내부통제 필수)
- 선행 조건: 정보보호팀과 MCP 서버 보안 요건 협의 필요

**Phase 3 — 2027-H1: 전사 에이전트 네트워크**

```
[사내 시스템]          [에이전트 네트워크]
 DMS          ←→    문서 에이전트
 데이터플랫폼 ←→    분석 에이전트    ←→ 오케스트레이터 ←→ 사용자
 ETF운용시스템←→    운용 에이전트
 AX Hub       ←→    거버넌스 에이전트
```

- 에이전트가 사내 API를 자율 호출하여 멀티스텝 업무 자동 처리
- 실시간 모니터링 대시보드·이상 행동 알림

### 3.4 인프라 요건

Phase 2 착수를 위해 아래 인프라가 필요하다.

| 구성 요소 | 역할 | 비고 |
|-----------|------|------|
| MCP 서버 | 에이전트 ↔ 사내 시스템 게이트웨이 | 정보보호팀 협의 필요 |
| 에이전트 레지스트리 | 어떤 에이전트가 어떤 역할인지 관리 | AX Hub `/registry` 기확보 |
| 감사 로그 DB | 에이전트 전체 행동 기록·추적 | 내부통제 필수 요건 |
| API 게이트웨이 | 사내 시스템별 접근 권한 제어 | IT인프라팀 협의 필요 |

### 3.5 거버넌스 연계

A2A 환경에서도 기존 AI 거버넌스 체계가 그대로 적용된다.

- 에이전트가 수행하는 모든 작업은 AX Hub에 과제로 등록
- 에이전트 행동에 대한 책임 소재는 해당 에이전트를 등록한 크루·AX팀
- 기밀 데이터(G3) 접근은 에이전트도 사람과 동일한 승인 절차 적용
- 정기 감사: 에이전트 행동 로그를 분기 1회 감사팀이 검토

### 3.6 추진 우선순위

세 과제를 동시에 추진하면 실행력이 분산된다. 아래 순서를 권고한다.

```
2026-08  스킬 관리 체계 구축 (GitLab + AX Hub 카탈로그)
         ↓
2026-08  거버넌스 문서 관리 체계 확정 (SSOT 원칙 + 추가 문서 신설)
         ↓
2026-09  Phase 1 완전 안착 확인 (자동승인율·사용자 정착)
         ↓
2026-Q4  Phase 2 착수 (MCP 서버 구축·에이전트 오케스트레이터)
         ↓
2027-H1  Phase 3 기획 시작 (전사 에이전트 네트워크)
```
