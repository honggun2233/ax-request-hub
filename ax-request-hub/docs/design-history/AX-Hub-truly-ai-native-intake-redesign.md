# AX Hub 인테이크 재설계 — "챗봇 탈을 쓴 폼"에서 벗어나기

**작성일**: 2026-08-21
**배경**: Tier1 대화형 설계안이 "1/3, 2/3, 3/3 순차 질문" 구조라 실질적으로 정형 폼과 차이가 없다는 문제의식

---

## 1. 왜 지금 설계가 "AI답지" 않은가

| 특징 | 지금 설계 | 진짜 정형 폼 |
|---|---|---|
| 질문 순서 | 고정(부서→데이터→기밀등급) | 필드 순서 고정 |
| 한 번에 답하는 개수 | 1개씩 | 1개씩 |
| 이미 아는 정보도 물어봄 | 부서를 또 물어봄(로그인 정보에 이미 있음) | 매번 새로 입력 |
| AI의 역할 | 질문 문장을 자연어로 바꿔줌 | — |

**AI가 하는 일이 "질문을 대화체로 포장하는 것"뿐이라면, 이건 자동화가 아니라 UI 스킨입니다.** 진짜 AI를 쓴다는 건 AI가 **판단하고, 종합하고, 추론하는** 역할을 해야 한다는 뜻입니다.

---

## 2. 진짜 AI다운 설계로 가는 4가지 방향

### 방향1 — 이미 아는 건 절대 묻지 않는다

```
❌ "부서명을 알려주세요"
✅ 로그인 세션의 Employee.department를 그대로 채우고, 확신도 100%로 표시
   (다른 부서 소속으로 신청하는 예외 케이스만 "본인 소속(운용본부 퀀트운용팀) 맞나요?" 로 확인)
```

부서, 이름, 이메일처럼 시스템이 이미 아는 정보를 다시 묻는 건 AI 활용이 아니라 그냥 나쁜 설계입니다.

### 방향2 — 질문하지 말고, 자료를 던지게 하고 AI가 종합 추론

지금은 "말로 설명 → AI가 갭 찾음 → 하나씩 되물음" 순서인데, 이건 **입력 채널을 대화 하나로 제한**하기 때문에 생기는 문제입니다. 요즘은 md 파일, 슬랙 내보내기, PRD 초안, 회의록 캡처 등 **이미 존재하는 잡다한 자료**를 그냥 던지게 하는 게 훨씬 AI다운 방식입니다.

```
✅ "가진 자료를 다 던져주세요 — 슬랙 대화, 메모, 엑셀 스크린샷, 뭐든 좋습니다"
   [파일 여러 개 업로드] + [자유 텍스트 붙여넣기] 동시 지원

   AI가 여러 자료를 한꺼번에 종합해서 필드를 채우고,
   "이해한 내용" 요약을 먼저 보여준 뒤 → 정말 애매한 것만 확인
```

이게 진짜 "AI가 대신 일해주는" 경험입니다. 사람이 순서대로 질문에 답하는 게 아니라, 사람은 자료만 던지고 정리는 AI가 다 합니다.

### 방향3 — 질문이 아니라 "판단 + 확인"으로 바꾼다

인표님이 평소에 쓰시는 원칙("사소한 건 AI가 판단하고 사후 보고")을 인테이크 설계에 그대로 적용하는 게 맞습니다.

```
❌ "에이전트 유형이 뭔가요?" (열린 질문)
✅ "에이전트 유형: SKILL로 판단했습니다 (신뢰도 88%) — 아니면 [MCP][WEBAPP]로 변경"
   (버튼 3개, 기본값이 이미 선택된 상태 — 안 건드리면 그대로 진행)
```

**질문 대신 "AI의 판단 + 원클릭 정정"**으로 바꾸면 사람이 타이핑할 일이 훨씬 줄어들고, AI가 실제로 "일을 했다"는 느낌을 줍니다. 열린 질문은 AI가 진짜 모를 때만 씁니다.

### 방향4 — 순차 질문이 아니라 배치로 한 번에

지금 설계도 사실 "3가지 남았어요"라고 한 번에 보여줄 수 있는데 굳이 1/3, 2/3, 3/3으로 나눠서 왕복을 3번 만듭니다.

```
❌ 질문1 → 답변1 → 질문2 → 답변2 → 질문3 → 답변3  (왕복 3회)
✅ "3가지만 확인할게요" + 3개 입력란을 한 화면에 동시 표시  (왕복 1회)
```

정말로 순차적이어야 하는 경우(뒤 질문이 앞 답변에 따라 달라짐)만 나누고, 그렇지 않으면 한 번에 모아서 묻는 게 사람 시간을 덜 씁니다.

## 3. 재설계된 흐름

```
1단계: 자료 투척
  사용자: [슬랙 캡처.png] [회의메모.md] "이거 참고해서 만들어주세요"

2단계: AI 종합 이해 요약 (질문 없이 먼저 보여줌)
  AI: "이해한 내용:
       펀드 보고서를 자동화하려는 프로젝트네요.
       운용본부 퀀트운용팀(로그인 정보 기준), 엑셀→Word 수작업을
       주 3회·건당 2시간 하고 계신 걸로 보입니다.

       판단한 것 (틀리면 바로 옆에서 수정 가능):
       · 에이전트 유형: SKILL (신뢰도 90%)
       · 예상 데이터: 일별 NAV, 포트폴리오 구성 — 자료에서 언급됨
       · 공개범위: 팀 단위 (기본값)

       확인이 꼭 필요한 것 (2가지):
       · 이 데이터는 기밀등급이 어떻게 되나요? [G1][G2][G3]
       · 이 데이터, 카탈로그에 등록된 게 맞나요? [예][아니오, 신규 데이터입니다]"

3단계: 원클릭 확인 (버튼 위주, 타이핑 최소화)
  사용자: [G2] [예] 클릭

4단계: 최종 확인 화면 (기존 설계와 동일)
```

**왕복 횟수**: 기존 설계는 "설명하기 → 5번의 질문응답 → 최종확인" = 최소 6~7턴. 재설계는 "자료던지기 → 확인 1턴 → 최종확인" = 3턴.

---

## 4. 기존 설계에서 유지해야 할 것

방향2~4는 "어떻게 채우는가"를 바꾸는 것이고, **"무엇을 반드시 확인해야 하는가"는 원안 그대로 유지**합니다:

- 기밀등급은 AI 추정값이라도 반드시 사람이 명시적으로 확인 (컴플라이언스 리스크라 자동 통과 불가)
- 데이터 요건은 "없음"도 명시적 선택 — 묵시적 통과 없음
- 필수 5개 필드(제목·부서·목적·As-Is·기대효과) 완전성 검증

이 세 가지는 원안 설계자가 정확히 짚은 부분입니다 — "AI가 편하게 만든다"와 "컴플라이언스상 반드시 사람 확인이 필요한 지점"을 구분한 게 맞습니다. 방향2~4는 그 확인 지점에 도달하기까지의 과정을 줄이는 것이지, 확인 자체를 없애는 게 아닙니다.

## 5. 개발 반영 가이드

```
1. /api/intake/chat → /api/intake/synthesize 로 재설계
   - 입력: 여러 파일 + 자유텍스트를 한 번에 받음 (배열)
   - 출력: 필드별 { value, confidence, source } — 어느 자료에서 이 값을 뽑았는지 추적 가능해야 신뢰 생김

2. 로그인 세션 정보(department, email)는 인테이크 시작 시점에 이미 채워서 시작
   - Employee 테이블 조회, AI 호출 이전에 선반영

3. 확신도 기반 UI 분기
   - confidence >= 임계값 → 값 표시 + [수정] 버튼만 (기본 선택됨)
   - confidence < 임계값 → 입력 필요 필드로 분류, 배치로 한 화면에 모아 표시

4. 기밀등급·데이터요건은 confidence 무관하게 항상 명시적 확인 UI로 고정
   (이 두 개는 방향3의 "판단+확인" 대상에서 제외 — 항상 사람이 최종 클릭)

5. RAG 확장 (후속, 우선순위 낮음)
   - 과거 승인된 유사 Project를 검색해서 "이전 사례는 이랬습니다" 참고자료로 제시
   - 인테이크 정확도를 자료 종류가 늘수록 계속 개선 가능한 구조로 설계
```

## 6. 핵심 판단

**질문을 잘 만드는 것보다 "질문 자체를 줄이는 것"이 더 AI다운 방향입니다.** 지금 설계는 질문 문장을 자연스럽게 다듬는 데 공을 들였는데, 진짜 AI 활용은 애초에 물어볼 것 자체를 줄이는 데 있습니다 — 이미 아는 걸 안 묻고, 자료를 종합해서 스스로 판단하고, 정말 애매하거나 컴플라이언스상 필수인 것만 사람에게 넘기는 것. 그게 인표님이 원래 지적하신 "예전 스타일 드롭다운·직접입력" 문제의 진짜 해결책입니다.
