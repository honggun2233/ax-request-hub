## 1. 목적 및 배경

삼성자산운용 전직원 500명 대상 생성형 AI 거버넌스를 단일 Hub에서 통합 관리한다.  
- 1차 배분: 8월 중 150명 우선 지급 (L1~L2 중심)  
- 기존 AX Request Hub(과제 심사·스코어카드) 기능 포함하여 확장  
- 기존 엑셀 관리 데이터 마이그레이션 지원  

---

## 2. 핵심 원칙

- **Hub = 오케스트레이션 레이어**: 정책 정의·기록·모니터링은 Hub에서. 실행(API 키 발급, 토큰 제한 적용)은 각 서비스 콘솔(OpenAI Enterprise, Claude for Work)에서. 연동 전에는 AX팀이 Hub 화면 보고 수동 적용.
- **토큰 한도는 배분 전에**: 서비스 발급 전 레벨별 한도가 Hub에 먼저 정의되어야 함.
- **연동 점진적 확장**: Phase 1은 수동 + Hub 기록. Phase 2에 API 자동화.

## 3. 사용자 역할 (RBAC)

| 역할 | 접근 범위 |
|------|---------|
| **일반 직원** | 내 레벨 신청/조회, 내 서비스 배분 확인, 내 사용량·한도, 과제/Agent 신청 |
| **부서장** | 부서원 현황 조회, 레벨 추천서 작성 |
| **AX팀 (관리자)** | 전체 관리, 레벨 심사·부여, 배분 정책, 엑셀 업/다운로드, 한도 설정, 감사 |
| **C-level** | KPI 요약 대시보드 (읽기 전용) |

## 4. 핵심 사용자 여정

```
① 직원 → Hub에서 AI 레벨 신청 (자기소개·교육이수·활용계획 작성)
        ↓
② AX팀 → 관리 포털에서 심사 → 레벨 부여 (L1~L4)
        ↓
③ Hub → 배분 정책 자동 생성 (레벨에 맞는 서비스 목록 + 토큰 한도)
        ↓
④ AX팀 → 각 서비스 콘솔에 수동 적용 (추후 API 자동화)
        ↓
⑤ 직원 → 배분된 AI 서비스 사용 시작
   직원 → 과제 생기면 과제 신청 → 6차원 스코어카드 심사
   직원 → Agent 만들면 Agent 등록
        ↓
⑥ AX팀 → 실시간 사용량 모니터링 (Hub 대시보드)
        ↓
⑦ 분기 평가 → 레벨업 심사 or Agent 성과 평가 → 배분 조정
```

## 5. 7개 모듈 상세

### 모듈 1: 직원 AI 레벨 관리

**직원 포털**
- 레벨 신청 폼: 이름·부서·직급, 교육 이수 현황, 활용 계획, 부서장 추천서 업로드
- 레벨 신청 이력 조회, 현재 레벨 확인
- 레벨업 신청 (조건 충족 시)

**AX 관리**
- 신청 목록 (대기/심사중/완료 칸반)
- 심사 화면: 신청 내용 검토 + 레벨 부여 + 코멘트
- 60일 이내 처리 SLA 모니터링
- **엑셀 업로드**: 기존 직원 레벨 데이터 일괄 등록 (헤더: 사번·이름·부서·레벨·부여일·비고)
- **엑셀 다운로드**: 현재 전체 직원 레벨 현황 추출

**DB 엔티티**: `Employee`, `LevelApplication`, `LevelHistory`

---

### 모듈 2: 서비스 배분

**직원 포털**
- 내가 받은 서비스 목록 (서비스명·계정·만료일·상태)
- 추가 배분 신청 (레벨 기준 미달 시 차단)

**AX 관리**
- 레벨별 배분 정책 설정 (어떤 레벨에 어떤 서비스를)
  - L1: Gemini, GPT for Excel
  - L2: GPT Enterprise, Claude.ai
  - L3: Codex, Claude Code, Antigravity
  - L4: AI 격리환경, AWS Bedrock
- 직원별 발급 이력 (서비스·발급일·회수일)
- 일괄 발급 (레벨 변경 시 자동 정책 적용 알림 생성)
- 퇴직·이동 시 회수 워크플로우

**DB 엔티티**: `DistributionPolicy`, `ServiceAllocation`

---

### 모듈 3: 토큰·비용 관리

**핵심 원칙**: 레벨 부여 → 서비스 발급 전에 한도 먼저 설정

**직원 포털**
- 내 이번 달 사용량 (서비스별, 프로젝트별)
- 한도 대비 잔여량 시각화
- 80% 도달 시 경고 배너

**AX 관리**
- 3단계 한도 정의
  - 회사 전체 한도 (월 예산 상한)
  - 직원/레벨별 한도
  - 건별 한도 (1회 API 호출 최대)
- 사용량 대시보드: 모델별·부서별·과제별 집계
- 이상 사용 알림: 전주 대비 2배 초과 시 24시간 내 확인
- 경량 모델 전환 권고 (분기 1회 자동 리포트)
- 사용량 데이터: Phase 1 수동 입력 / Phase 2 API 자동 pull

**DB 엔티티**: `TokenPolicy`, `UsageRecord`, `UsageAlert`

---

### 모듈 4: AI 과제 심사 (기존 확장)

기존 AX Request Hub의 핵심 기능. 확장 사항:
- 과제와 직원 레벨 연동 (L3 미만은 일부 과제 유형 차단)
- 과제별 토큰 예산 신청·승인 플로우 추가
- 과제 상태와 Agent 등록 연결 (과제 승인 → Agent 등록 가능)

기존: 6차원 스코어카드, 자동승인/에스컬레이션, 감사로그 유지

---

### 모듈 5: Agent 라이프사이클

**직원 포털**
- Agent 등록 신청 (명칭·목적·사용 모델·연계 과제·위험 자가진단)

**AX 관리**
- 위험 등급 부여: 저위험/중위험/고위험
  - 저위험: 협의체 보고 후 운영
  - 중위험: 협의체 심의 + 월별 모니터링
  - 고위험: 위원회 최종 승인
- Agent 상태 관리: 등록→운영→평가→전사확산 or 폐기
- 분기 성과 평가 스케줄 자동 생성
- Agent HR 등재 (우수 Agent → 위원회 전사확산 결정)
- Prompt Library: Agent별 컨텍스트 자산 저장·버전 관리

**DB 엔티티**: `Agent`, `AgentEvaluation`, `PromptLibraryEntry`

---

### 모듈 6: 감사·보안 로그

**AX 관리**
- 모든 레벨 부여·서비스 발급·과제 승인·Agent 등록 이력 (변경 불가 로그)
- 정책 위반 탐지: G2/G3 데이터 경로 위반, 한도 초과, 미승인 서비스 사용 신고
- API 키 관리 대장: 누가 어떤 키 보유, 만료일, 회수 이력
- 인시던트 관리: 발생→대응→종결 워크플로우
- 90일 로그 보존 (정보보호팀 DLP 연동은 Phase 2)

**DB 엔티티**: `AuditLog`, `PolicyViolation`, `ApiKeyRegistry`, `Incident`

---

### 모듈 7: 리터러시·교육 이력

**직원 포털**
- 교육 이수 현황 (AX팀 등록 기준)
- CREW 레벨 조회 (Lv.1 탐색가 / Lv.2 실험가 / Lv.3 개발자)
- CREW 신청 (조건 충족 시)

**AX 관리**
- 교육 과정 등록·이수 처리
- CREW 레벨 심사
- AI Coach·Master 인증 현황 (배정 부서, 담당 인원)
- 우수 사례 공모전 접수·평가·Prompt Library 등재

**DB 엔티티**: `TrainingRecord`, `CrewLevel`, `InstructorCertification`

## 8. MVP vs Phase 2

### Phase 1 MVP (8월 배분 전 완료 목표)

- [ ] 인증 시스템 (NextAuth + RBAC 4단계)
- [ ] 모듈 1: 직원 레벨 신청→심사→부여 + 엑셀 업/다운로드
- [ ] 모듈 2: 서비스 배분 정책 설정 + 직원 배분 조회
- [ ] 모듈 3: 토큰 한도 정의 + 수동 사용량 입력 + 경고 알림
- [ ] 직원 포털 /me 통합 대시보드

### Phase 2 (MVP 이후)

- [ ] 모듈 4 과제심사 완전 통합 (기존 코드 흡수)
- [ ] 모듈 5 Agent 라이프사이클
- [ ] 모듈 6 감사·보안 로그 고도화
- [ ] 모듈 7 리터러시·교육
- [ ] OpenAI/Claude API 사용량 자동 pull 연동
- [ ] 이상 탐지 자동화
- [ ] PostgreSQL 마이그레이션 (직원 수 증가 대비)
