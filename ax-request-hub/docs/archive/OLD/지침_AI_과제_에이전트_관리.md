## 1. AI CREW 정의 및 역할

**AI CREW**는 각 부서에서 AI 활용을 선도하는 현업 담당자다. 타사의 "AI 챔피언"에 해당하는 삼성자산운용 공식 명칭이다.

| 역할 | 내용 |
|------|------|
| **AI 활용 선도** | 부서 내 AI 활용 사례 발굴·공유 |
| **AX팀 창구** | 부서와 AX팀 사이의 1차 소통 창구 |
| **과제 발굴** | 부서 업무 중 AI 적용 가능 영역 탐색 |
| **과제 정의서 작성** | 1차 과제 정의서(v0) 작성 및 AX팀 제출 |
| **UAT 담당** | 파일럿 단계 사용자 인수 테스트(UAT) 수행 |
| **교육 참여** | AX팀 주관 AI 역량 강화 프로그램 참여 |

**AI CREW 선발 기준**: 부서장 추천 + AX팀 인터뷰 + 기초 AI 이해도 확인  
**운영**: 부서당 1~2명, 분기 1회 AI CREW 전체 회의

## 2. AI 과제 단계 (Phase 0 → Phase 6)

모든 유형 2 이상의 AI 과제는 아래 7단계를 거쳐 승격된다.

### Phase 0 — 발굴 (Idea)

- **담당**: AI CREW + 현업 담당자
- **활동**: 업무 문제 정의, AI 적용 가능성 탐색
- **산출물**: 아이디어 메모 (자유 형식)
- **기준**: AX팀에 구두·문서로 사전 문의 가능

### Phase 1 — 기획 (Initiation)

- **담당**: AI CREW + AX팀
- **활동**: 과제 정의서 v0 작성, 위험등급 1차 판단, 데이터 가용성 확인
- **산출물**: 과제 정의서 v0 (8개 필드, 하단 서식 참조)
- **기준**: AX팀 접수 → 10영업일 내 기획 게이트 결과 통보

### Phase 2 — 설계 (Design)

- **담당**: AX팀 + AI CREW
- **활동**: 아키텍처 설계, 기밀등급 확정, 에이전트 유형 결정
- **산출물**: 과제 정의서 v1 (v0 + 아키텍처 8개 추가 필드), 설계 리뷰서
- **기준**: 고위험 과제는 컴플라이언스 사전 검토 필수

### Phase 3 — MVP 개발

- **담당**: AX팀 (필요 시 외부 개발 협력)
- **활동**: 최소 기능 구현, 단위 테스트
- **산출물**: 작동하는 MVP, 테스트 결과서
- **기준**: G2 이상 데이터는 개발 단계에서 실 데이터 사용 금지 (테스트 데이터만)

### Phase 4 — 심사 (Review)

- **담당**: AX팀 + 컴플라이언스 + 정보보안
- **활동**: 위험 평가, 보안 검토, 데이터 적합성 확인
- **산출물**: 심사 보고서, 위험 평가서
- **기준**: AI 자동 평가 70점 이상 + G1/G2 → 파일럿 진입. 고위험은 IT업무개발팀장 승인 필요

### Phase 5 — 파일럿 (Pilot)

- **담당**: AI CREW + AX팀 공동
- **활동**: 실 업무 환경에서 제한적 운영, UAT, KPI 측정
- **기간**: 중위험 4~6주, 고위험 8주
- **산출물**: UAT 결과, KPI 달성 현황, 사고 0건 확인서
- **기준**: 위험등급별 KPI 기준 달성 시 운영 승격 신청 가능

### Phase 6 — 배포·운영 (Deployment)

- **담당**: AX팀 → IT업무개발팀 이관 (안정 운영)
- **활동**: Agent ID 발급, 모니터링 설정, 비용 추적 시작
- **산출물**: 운영 명세서, 모니터링 대시보드 설정
- **기준**: 위험등급별 승인자 최종 승인 후 배포

## 4. AI 자동 평가 기준 (과제 심사 6차원, 100점)

| 차원 | 배점 | 평가 기준 |
|------|------|---------|
| 임팩트 | 25 | 영향 인원·빈도·전략 정합성 |
| ROI | 25 | 시간·비용 절감, 수익 기여 추정 |
| 기밀등급 | 15 | G1 고배점, G3 저배점 + 복잡도 |
| 난이도 역산 | 15 | 낮은 난이도 = 고점 (빠른 성과 우선) |
| 현업 준비도 | 10 | 데이터 가용성, AI CREW 유무 |
| 전략 정합성 | 10 | AX 로드맵 등대 과제와 연관성 |

- **70점 이상 + G1/G2** → 자동 PoC 승인
- **70점 미만 또는 G3** → AX팀장 판단
- **경계(68~72점)** → 자동 처리 금지, 팀장 직접 검토

## 5. 에이전트 라이프사이클 관리

### 5-1. 관리 대상 기준

다음 조건을 **모두** 충족하는 AI를 "에이전트"로 등록하고 라이프사이클 관리한다.

- 자동화 실행이 되고 (사람이 매번 수동 실행하지 않음)
- 사람 승인 없이 반복 동작하며 (스케줄·트리거 기반)
- 외부 도구·API를 호출하거나 데이터를 변경할 수 있다

→ 세 조건 중 하나라도 빠지면 "APA" 또는 "AI 서비스 활용"으로 분류

### 5-2. Agent ID 체계

```
형식: AX-{YYYY}-{유형코드}-{순번}

유형코드:
  APA = AI 자동화 파이프라인 (유형 2)
  AGT = 단독 에이전트 (유형 3)
  MAS = 멀티 에이전트 시스템 (유형 4)

예: AX-2026-AGT-001, AX-2026-APA-003
```

Agent ID는 운영 승격 시 AX팀이 발급한다.

### 5-3. 에이전트 상태 관리

| 상태 | 설명 | 전환 조건 |
|------|------|---------|
| 🟡 등록신청 | 심사·파일럿 단계 | 과제 정의서 제출 후 |
| 🟢 Active | 정상 운영 중 | 운영 승격 승인 후 |
| 🔵 Suspended | 일시 중단 | 점검·업데이트·사고 조사 중 |
| 🔴 Retired | 공식 폐기 | 폐기 기준 충족 시 |
| 📦 Archived | 기록 보존 | 폐기 후 1년 보존 |

### 5-4. 폐기 기준

다음 중 **하나라도** 해당하면 폐기 절차를 시작한다.

| 기준 | 내용 |
|------|------|
| KPI 지속 미달 | 목표 KPI 60% 미달 3개월 연속 |
| 보안 사고 | 데이터 유출·무단 접근 사고 1건 |
| 업무 소멸 | 담당 업무·프로세스 자체가 없어진 경우 |
| 대체 확정 | 더 나은 솔루션으로 공식 대체 결정 |
| 미사용 | 12개월 연속 사용 기록 0건 |

폐기 시 감사 로그는 아카이브 기간 동안 보존하고, Agent ID는 재사용하지 않는다.
