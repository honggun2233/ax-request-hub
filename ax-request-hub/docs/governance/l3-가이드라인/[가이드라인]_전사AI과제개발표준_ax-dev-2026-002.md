## 1. 적용 범위

이 표준은 삼성자산운용 임직원이 직접 개발하거나 외주·AI 도구로 생성한 AI 에이전트·자동화 도구를 **전사에 배포**할 때 반드시 따라야 하는 요건이다.

| 적용 대상 | 미적용 |
|-----------|--------|
| AX Request Hub에 과제 신청한 모든 AI 과제 | 개인 업무 자동화 (배포 안 함) |
| 전사 공용 AI 도구·에이전트 | PoC 단계 (승인 전) |
| GPT Enterprise / 내부 서버 배포 서비스 | 개인 실험·학습 목적 |

## 2. 개발 3단계 요건

```
[Phase 1: PoC]  →  [Phase 2: AX팀 검토 & Gate 통과]  →  [Phase 3: 전사 배포]
   임직원 개발        AX팀 인수 + 기술 검증                  내부 인프라 배포
```

### Phase 1 — PoC (임직원 자체 개발)

임직원이 자율적으로 개발하는 단계. 엄격한 제약은 없으나 아래 2가지는 필수다.

- **기밀 데이터 사용 금지**: 운영 DB, 개인정보, 기밀 문서를 개발·테스트에 사용하지 않는다. 샘플·더미 데이터만 허용.
- **AX Request Hub 과제 등록**: 전사 배포를 목표로 개발을 시작하면 반드시 과제를 신청한다. 개발 완료 후 신청은 불가하다.

### Phase 2 — AX팀 검토 & Gate 통과

AX팀이 PoC를 인수받아 전사 배포 가능 여부를 판단하는 단계. (「AI 운영 지침」 제10조)

**Gate 2 기술표준 자가점검 (4항목 전부 필수):**

| 항목 | 요건 | 확인 방법 |
|------|------|-----------|
| API 명세 | 입력·출력 인터페이스 문서화 | OpenAPI 3.0 또는 동등한 명세서 |
| 데이터 기밀 처리 계획 | 처리 데이터의 G1/G2/G3 등급 명시 | 데이터 목록 + 등급 표 제출 |
| 감사로그 설계 | 주요 동작 이벤트 로그 구조 정의 | 로그 항목·보존 기간 명세 |
| 테스트 커버리지 | 비즈니스 로직 80% 이상 단위 테스트 통과 증명 | 테스트 결과 보고서 또는 커버리지 스크린샷 |

> 4항목 미충족 시 Gate 2 보류. AX팀 컨설팅 후 재신청 가능. 보류 ≠ 거부.

**AX팀 코드 리뷰:**
- AX팀이 코드 보안·성능·유지보수성 검토
- 피드백 반영 후 AX팀 인수 완료

### Phase 3 — 전사 배포

AX팀이 운영 인프라에 배포하는 단계. 임직원이 직접 배포하지 않는다.

### 브랜치 규칙 (내부 GitLab 이관 후)

```
main          배포 브랜치 (AX팀만 머지 가능)
develop       통합 개발 브랜치
feat/<기능명>  기능 개발 (임직원 작업)
fix/<내용>    버그 수정
```

- 임직원은 `feat/` 브랜치에서 개발 후 PR 생성
- AX팀이 코드 리뷰 → `develop` 머지 → 테스트 → `main` 머지 → 배포
- `main` 직접 커밋 금지

## 4. 표준 기술 스택 (강제)

> **LLM 도구(Claude Code, Cursor 등)를 쓰면 언어 장벽이 없다.**  
> 임직원이 자유롭게 언어를 선택하면 AX팀이 인수받을 때 수습에 과도한 시간이 소요된다.  
> 따라서 **처음 PoC 단계부터 아래 표준 스택으로 개발한다.** 예외 시 AX팀 사전 승인 필수.

### 승인 스택

| 용도 | 표준 | 버전 | 비고 |
|------|------|------|------|
| AI 에이전트 · 자동화 · 배치 | **Python** | 3.11 이상 | 사실상 유일한 선택 |
| 웹 UI · 관리 포털 | **Next.js (TypeScript)** | 14 이상 | AX Hub와 동일 스택 |
| API 서버 (Python) | **FastAPI** | 최신 stable | 필요 시 |
| DB (개발) | **SQLite** | — | Prisma ORM 권장 (TS), SQLAlchemy (Python) |
| DB (운영) | **PostgreSQL** (내부 서버) | — | 데이터플랫폼팀 협의 필요 |
| LLM SDK | **Anthropic Claude API** | 최신 SDK | 다른 LLM 사용 시 AX팀 사전 승인 |
| 패키지 관리 | `requirements.txt` (Python) / `package.json` (Node) | — | 버전 핀 필수 |

### 비승인 스택 (사용 금지)

| 분류 | 금지 항목 | 이유 |
|------|-----------|------|
| 언어 | Java, Kotlin, Go, Ruby, PHP 등 Python/TS 외 | AX팀 유지보수 불가 |
| 프레임워크 | Django, Flask, Express (단독), Spring | 표준 스택과 혼재 |
| LLM | OpenAI API, Google Gemini API (무승인) | 보안 정책, 비용 통제 |
| DB | MySQL, MongoDB, Redis (무승인) | 내부 인프라 미지원 |
| 배포 | Vercel, GCP, Azure (사전 승인 없는 외부 서비스) | 내부 인프라 미지원 / 보안 정책 미검토 |

## 5. 코드 품질 기준

### 필수 요건

1. **API 키·비밀번호 하드코딩 금지**
   - 환경변수(`.env`) 또는 시크릿 관리 도구 사용
   - `.env` 파일은 `.gitignore`에 반드시 포함

2. **에러 처리 필수**
   - 외부 API 호출, DB 접근, 파일 I/O는 모두 예외 처리
   - 에러 발생 시 서비스 중단이 아닌 fallback 동작 정의

3. **로깅 구현**
   - 주요 동작(시작·완료·에러)은 반드시 로그 기록
   - 로그에 개인정보·기밀 데이터 포함 금지

4. **의존성 명시**
   - Python: `requirements.txt` 또는 `pyproject.toml`
   - Node.js: `package.json` (버전 고정 권장)
   - 미승인 외부 패키지 사용 시 AX팀 사전 협의

5. **문서화**
   - README: 설치 방법, 실행 방법, 환경변수 목록 필수
   - 핵심 함수·API: 목적과 입출력 설명

## 6. 데이터 거버넌스

### 기밀 등급 정의

| 등급 | 정의 | 예시 | 처리 원칙 |
|------|------|------|-----------|
| G1 공개 | 공개 가능 데이터 | 공시 정보, 뉴스 | 제한 없음 |
| G2 내부 | 사내 공유 가능 | 내부 보고서, 운용 일반 데이터 | 사내 시스템 내 보관 |
| G3 기밀 | 제한적 접근 | 미공개 운용 전략, 고객 정보, 인사 정보 | 온프레미스만, 암호화 필수 |

### 데이터 사용 원칙

- **G3 기밀 데이터**: 외부 클라우드(GitHub, AWS, GPT Enterprise 등) 전송 절대 금지
- **G2 이상 데이터 연동**: 데이터플랫폼팀 공식 협의 필수 (임직원이 직접 운영 DB 접근 금지)
- **개인정보 처리**: 정보보호팀 사전 검토 필수
- **PoC 개발 시**: 샘플 데이터 또는 비식별화된 데이터만 사용. 데이터 소관 부서 확인 후 사용한다.

## 7. 보안 요건

| 항목 | 요건 |
|------|------|
| 인증 | 서비스 접근 시 임직원 인증(AD/SSO) 연동 권장 |

| 비밀 관리 | API 키·DB 패스워드는 환경변수 또는 Vault 사용, 코드 내 금지 |

- 사전 승인 없이 전사 공유하는 행위 (팀 내 공유는 허용)

## 10. KPI & 운영 (전사 배포 후)

전사 배포된 AI 서비스는 **AX Hub 에이전트 레지스트리**에 등록되어 지속 관리된다.

### 등록 필수 항목

```
서비스명       예: "운용 보고서 자동 요약"
담당 부서      예: "운용본부 리서치팀"
KPI 지표       예: "보고서 처리 시간 단축률"
KPI 목표       예: 70%
측정 방법      예: "월별 처리 건수 / 평균 소요 시간 측정"
측정 주기      월별 또는 분기별
```

### 운영 지속 기준

- KPI 50% 미만 → DEGRADED 상태 전환
- DEGRADED 상태 3개월 연속 지속 → 폐기 후보 검토
- 12개월 미사용 → 자동 폐기 검토
- 보안 위반 발생 → 즉시 서비스 중단 + 소속 부서장 보고

## 11. 라이프사이클

```
[AX Hub 신청] → [PoC 개발] → [Gate 2 제출 + AX팀 검토] → [파일럿] → [전사 배포(ACTIVE)]
                                                                        ↓
                                                               [성능 저하(DEGRADED)]
                                                                        ↓
                                                               [서비스 종료(RETIRED)]
```

| 상태 | 의미 | 전환 조건 |
|------|------|-----------|
| PoC | 임직원 개발 중 | — |
| 신청됨 | AX Hub 접수 완료 | AX Request Hub 신청 |
| 검토 중 | AX팀 코드리뷰·Gate 2 | AX팀 인수 |
| 파일럿 | 소규모 운영 테스트 | 70점 이상 승인 |
| ACTIVE | 전사 배포 중 | UAT 통과 + 실무협의체 안정성 검증 → AX위원회 최종 심의·승인 |
| DEGRADED | 성능 저하 감지 | KPI 50% 미만 또는 에러율 과다 |
| RETIRED | 서비스 종료 | AX팀 + 담당 부서 합의 |

## 12. 자주 묻는 질문

**Q. 코드를 잘 모르는데도 이 표준을 따라야 하나요?**  
Phase 1(PoC)은 자율 개발이다. AX팀에 인계하면 AX팀이 기술 요건을 충족시켜 준다. 단, 기밀 데이터 미사용과 과제 사전 등록은 누구나 준수해야 한다.

**Q. GitHub에 올려도 되나요?**  
내부 데이터를 쓰지 않는 현재 단계에서는 private repo 허용이다. 내부 데이터가 들어가는 순간부터 내부 GitLab 이관이 필수다.

**Q. Gate 2 항목이 부족하면 개발을 못 하나요?**  
Gate 2 보류는 거부가 아니다. AX팀과 컨설팅하면서 보완하면 된다. 전사 배포 전까지 충족하면 된다.

**Q. 팀 내부에서만 쓰는 건 이 표준 적용 대상인가요?**  
팀 내부 배포는 적용 대상이 아니다. 전사 공용으로 배포할 때만 적용된다.
