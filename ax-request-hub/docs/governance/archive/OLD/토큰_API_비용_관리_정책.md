## 핵심 원칙

1. **중앙 발급**: API 키는 AX팀이 중앙 관리. 현업이 개인 카드로 가입·결제 금지.
2. **과제 단위 추적**: 비용은 과제 ID에 귀속. "AX팀 전체 비용"이 아니라 "AX-2026-AGT-001 비용".
3. **단계별 한도**: 개발 < 파일럿 < 운영. 각 단계에서 필요 이상 쓰지 않는다.
4. **초과 알림**: 한도 80% 도달 시 자동 알림. 100% 도달 시 자동 정지 또는 승인 요청.

## 1. API 키 발급 체계

### 1-1. 현업이 직접 하면 안 되는 것
- 개인 카드로 ChatGPT Plus / Claude Pro 등 가입 후 업무에 사용 → **사용 기록 없음, 기밀 유출 위험**
- 개인 계정으로 API 키 발급 → **비용 추적 불가, 보안 위반 가능**
- 팀 공용 API 키를 코드에 하드코딩 → **키 유출 시 전체 피해**

### 1-2. 올바른 발급 절차

```
현업 개발자 → AX팀에 API 키 신청 (과제 ID + 용도)
           → AX팀장 승인 (한도 배정 포함)
           → AX팀이 환경변수/Vault로 키 전달 (코드에 직접 넣지 않음)
           → 사용량 모니터링 자동 시작
```

### 1-3. 키 저장 규칙
- 키는 `.env` 파일 또는 비밀 관리 도구에만 저장
- `.env`는 `.gitignore`에 포함 (GitHub에 절대 올리지 않음)
- 로컬 개발: `.env` 파일
- 서버 배포: 환경 변수 주입 (Vercel Env, Docker Secret 등)

| 개발·테스트 | $20 / 과제 | AX팀 자체 |
| 파일럿 | $100 / 과제 | AX팀장 승인 |
| 운영 (G1) | 과제별 예산 책정 | IT업무개발팀장 승인 |

### 2-1. 한도 초과 프로세스

```
사용량 80% 도달 → AX팀 + 담당자 알림 (자동)
사용량 100% 도달 → 에이전트 자동 일시정지 OR 팀장 긴급 승인 요청
                 (에이전트 정지가 업무 중단을 야기하면 → 즉시 승인 루트)
월말 → 과제별 비용 정산 리포트 → AX팀장 보고
```

## 3. 모델별 비용 특성 (과제 설계 시 참고)

> 아래 가격은 2026-07 기준. 변동될 수 있으므로 과제 설계 시 최신 가격 확인.

| 모델 | 입력 토큰 비용 | 출력 토큰 비용 | 적합 용도 |
|------|-------------|-------------|---------|
| claude-haiku-4-5 | 저렴 | 저렴 | 대량 분류, 단순 요약 |
| claude-sonnet-4-6 | 중간 | 중간 | 일반 업무 에이전트 (현재 주력) |
| claude-opus-4 | 고가 | 고가 | 복잡한 추론, 핵심 의사결정만 |

**비용 절감 원칙**:
- 단순 분류·라우팅 → Haiku 먼저 시도
- RAG 검색 → 검색은 임베딩 비용, 요약만 LLM 비용
- 캐싱 활용: 동일 프롬프트 반복 → Prompt Cache로 비용 절감
- 배치 처리: 실시간이 아닌 업무는 Batch API 활용 (비용 50% 절감)
