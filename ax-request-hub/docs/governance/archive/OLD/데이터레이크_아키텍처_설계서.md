## 1. 기술 스택 선정 근거

### 최종 결정: DuckDB MVP → PostgreSQL 전환 준비 완료

| 기준 | DuckDB (MVP) | PostgreSQL (성장기) | 하이브리드 |
|---|---|---|---|
| 설치·운영 | 파일 1개, 의존성 없음 ✅ | 서버 데몬·백업 체계 필요 | 복잡도 높음 |
| 온프레미스 | 완전 지원 ✅ | 완전 지원 ✅ | 완전 지원 ✅ |
| 분석 성능 | 컬럼형 OLAP 최적화 ✅ | OLTP 우선, 분석 부하 시 인덱스 필요 | — |
| AI 소비 | Python DuckDB 0-의존성, Pandas 직접 연계 ✅ | psycopg2 + 연결풀 설정 필요 | — |
| 확장성 | 단일 파일 한계 (~수십 GB 실용) | 무제한, 멀티 컨넥션 ✅ | — |
| 전환 비용 | SQL 표준 준수, 추상화 계층 시 전환 용이 ✅ | — | — |

**MVP 선택 이유**: 지금 당장 운영 인프라 없이 파일 1개로 시작, 데이터 볼륨이 실용 한계(~30GB)에 도달하면 PostgreSQL로 DDL 재사용해 전환.

**전환 트리거**: (a) 파일 크기 20GB 초과, (b) 동시 접근 3개 이상, (c) 운용시스템 Spring MSA 실시간 연결 필요 시.

### 3-3. Analytics Layer — AI 핸드오프 뷰

```sql
-- ETF 성과 대시보드 뷰 (AI 프롬프트 주입용)
CREATE VIEW analytics.etf_performance_summary AS
SELECT
    n.portfolio_id,
    n.as_of,
    n.nav,
    LAG(n.nav) OVER (PARTITION BY n.portfolio_id ORDER BY n.as_of) AS prev_nav,
    (n.nav - LAG(n.nav) OVER (PARTITION BY n.portfolio_id ORDER BY n.as_of))
        / NULLIF(LAG(n.nav) OVER (PARTITION BY n.portfolio_id ORDER BY n.as_of), 0) AS daily_return,
    n.source_system,
    n.is_mock
FROM clean.nav_timeseries n
WHERE n.is_mock = false;

-- 백테스팅 결과 요약 뷰 (Look-Ahead Bias 경고 포함)
CREATE VIEW analytics.backtest_quality_report AS
SELECT
    run_id,
    strategy_name,
    run_date,
    total_return,
    cagr,
    sharpe_ratio,
    max_drawdown,
    look_ahead_bias,
    survival_bias,
    CASE
        WHEN look_ahead_bias = 'HIGH' OR survival_bias = 'PRESENT'
        THEN 'UNRELIABLE — dataGap 명시 필요'
        WHEN look_ahead_bias = 'MEDIUM'
        THEN 'CONDITIONAL — PIT 보완 후 활용'
        ELSE 'RELIABLE'
    END AS quality_grade
FROM clean.backtest_results;

-- 미디어 신호 최신 뷰 (AI 프롬프트 주입용, 원본 본문 미포함)
CREATE VIEW analytics.media_signal_latest AS
SELECT
    company_name,
    MAX(signal_date) AS latest_date,
    SUM(news_mentions) AS news_7d,
    SUM(social_mentions) AS social_7d,
    AVG(avg_sentiment) AS sentiment_7d_avg,
    BOOL_OR(influencer_flag) AS has_influencer
FROM clean.media_daily_signals
WHERE signal_date >= CURRENT_DATE - INTERVAL '7 days'
GROUP BY company_name;
```

## 4. 수집 파이프라인 설계 (소스별)

### 4-1. MH LAB SQLite → DuckDB

| 항목 | 내용 |
|---|---|
| **소스 경로** | `C:\project\mhlab-etf\data\mhlab.sqlite` |
| **수집 방식** | DuckDB `ATTACH` + INSERT SELECT (읽기 전용) |
| **스케줄** | 평일 18:00 KST (장 마감 후) |
| **중복 방지** | `UNIQUE(as_of, portfolio_id, source_system)` + `ON CONFLICT DO NOTHING` |
| **기밀등급** | G2 (사내 전용) |

```python
# pipeline/ingest_mhlab.py 핵심 패턴
import duckdb

def ingest_mhlab(lake_path: str, sqlite_path: str):
    con = duckdb.connect(lake_path)
    con.execute(f"ATTACH '{sqlite_path}' AS src (TYPE sqlite, READ_ONLY)")
    con.execute("""
        INSERT OR IGNORE INTO raw.mhlab_nav (as_of, portfolio_id, nav, raw_json, _source_file)
        SELECT date_val, portfolio_id, nav, to_json(src.nav_history), ?
        FROM src.nav_history
        WHERE date_val >= (SELECT COALESCE(MAX(as_of), '1900-01-01') FROM raw.mhlab_nav)
    """, [sqlite_path])
    con.execute("DETACH src")
```

### 4-2. ETF 백테스팅 결과 → DuckDB (P0-3 해소)

| 항목 | 내용 |
|---|---|
| **소스 경로** | `C:\project\ETF 상품 개발 프로젝트\data\outputs\{date}\*.json` |
| **현재 상태** | 날짜별 폴더에 docx·xlsx·png·txt 파일 존재. JSON 출력 없음(P0-3 미해소) |
| **수집 방식** | ① 상품개발 앱에서 BacktestResult → JSON 저장 (CTO 구현) → ② 파이프라인이 신규 JSON 감지 → DuckDB INSERT |
| **스케줄** | 실행 직후 즉시 + 일별 배치 스캔 |
| **중복 방지** | `run_id PRIMARY KEY` |
| **기밀등급** | G1 (공개 가능, 상품 출시 전까지 사내) |

**⚠️ CTO 선행 구현 필요:** 백테스팅 엔진에 `result.save_json(output_dir)` 추가 — 이 없이는 파이프라인 수집 불가.

### 4-3. 미디어 모니터링 Pkl → DuckDB

| 항목 | 내용 |
|---|---|
| **소스 경로** | `C:\project\ETF 상품 개발 프로젝트\data\cache\media_monitor_latest.pkl` |
| **수집 방식** | Python `pickle.load` → DataFrame → DuckDB INSERT |
| **스케줄** | 일별 14:00 KST (미디어 수집 완료 후) |
| **기밀등급** | G1 (공개 데이터 집계, 원본 URL 포함 시 G1 유지) |
| **주의** | `media_monitor_prev.pkl` 과 중복 제거 필수 (`collected_at` + `company_name` 키) |

```python
# pipeline/ingest_media.py 핵심 패턴
import pickle, duckdb

def ingest_media(lake_path: str, pkl_path: str):
    with open(pkl_path, 'rb') as f:
        data = pickle.load(f)  # DataFrame 또는 dict 예상
    # pickle 구조에 따라 파싱 — CTO가 스키마 확인 후 확정
    df = normalize_media_pkl(data)
    con = duckdb.connect(lake_path)
    con.execute("""
        INSERT OR IGNORE INTO raw.media_mentions
        SELECT _ingested_at=now(), _source_file=?, collected_at, company_name,
               mention_count, sentiment_score, channel, to_json(row)
        FROM df
    """, [pkl_path])
```

## 5. 파티셔닝 전략

DuckDB MVP 단계에서 물리적 파티셔닝은 불필요 (파일 단위 스캔이 이미 컬럼형 최적화). 대신 **논리적 파티셔닝 규약**으로 쿼리 성능 보장:

| 테이블 | 파티션 키 | 인덱스 |
|---|---|---|
| `raw.mhlab_nav` | `as_of` (DATE) | `(as_of, portfolio_id)` |
| `raw.backtest_runs` | `run_date` (DATE) | `run_id` UNIQUE |
| `raw.media_mentions` | `collected_at` (TIMESTAMPTZ) | `(company_name, collected_at)` |
| `clean.nav_timeseries` | `as_of` | `(as_of, portfolio_id, source_system)` UNIQUE |
| `clean.backtest_results` | `run_date` | `run_id` PK |
| `clean.media_daily_signals` | `signal_date` | `(signal_date, company_name)` PK |

**PostgreSQL 전환 시**: 위 파티션 키를 `PARTITION BY RANGE(as_of)` 월별 파티션으로 전환, DDL 재작성 최소화.

## 7. 기밀 경계 및 접근 제어

```
G1 공개 데이터 (KRX, DART, yfinance, 뉴스 집계)
  └─ AI 프롬프트 주입 허용 (집계·요약 레벨)
  └─ analytics.* 뷰 → Claude API 전달 가능
```

## 9. 추상화 계층 (PostgreSQL 전환 대비)

현재 DuckDB 의존성을 최소화하여 전환 비용을 낮춤:

```python
# pipeline/db_interface.py — 추상화 계층
from abc import ABC, abstractmethod

class DataLakeConnection(ABC):
    @abstractmethod
    def execute(self, sql: str, params=None): ...

    @abstractmethod
    def insert_dataframe(self, table: str, df): ...

class DuckDBConnection(DataLakeConnection):
    """MVP: DuckDB 구현"""
    def __init__(self, path: str):
        import duckdb
        self._con = duckdb.connect(path)

    def execute(self, sql, params=None):
        return self._con.execute(sql, params or [])

    def insert_dataframe(self, table, df):
        self._con.execute(f"INSERT INTO {table} SELECT * FROM df")

# class PostgreSQLConnection(DataLakeConnection):  ← 전환 시 구현
```

전환 시 `DuckDBConnection` → `PostgreSQLConnection` 교체만으로 파이프라인 재사용.

## 10. 품질 게이트 (수집 파이프라인 강제)

모든 수집 파이프라인은 아래 게이트를 통과해야 DuckDB에 적재:

```python
def quality_gate(df, source_id: str) -> bool:
    """False 반환 시 적재 거부, 알림 발송"""
    checks = [
        ("as_of 누락", df['as_of'].isna().sum() == 0),
        ("미래 날짜 방지", (df['as_of'] <= date.today()).all()),
        ("Mock 플래그 확인", 'is_mock' in df.columns),
        ("중복 키 없음", df.duplicated(subset=['as_of', 'source_key']).sum() == 0),
    ]
    failures = [name for name, passed in checks if not passed]
    if failures:
        log_and_alert(f"[{source_id}] 품질 게이트 실패: {failures}")
        return False
    return True
```
