# AI 과제 프로세스 단계 관리

> 문서번호: IT-AX-PROC-001  
> 버전: v1.0 | 작성: IT업무개발팀 AX/PI팀 | 2026-07-02

---

## 전체 흐름

```
[0. 발굴] → [1. 기획] → [2. 설계] → [3. MVP] → [4. 심사] → [5. 파일럿] → [6. 배포]
                ↑                                      ↑
           과제정의서 v0                           과제정의서 최종
```

각 단계는 게이트(Gate)로 구분된다. 게이트를 통과해야 다음 단계로 진행할 수 있다.

---

## 단계별 상세

### Phase 0 — 발굴 (상시)

**목적**: 과제 후보 식별  
**담당**: AX팀 PI + 현업 신청자  
**방법**: AX 포털 자유 신청 / AX팀 자체 발굴 / 부서 인터뷰

**이 단계에서 확인하는 것**:
- 어떤 문제를 풀려는가? (결과가 아닌 근본 원인)
- 지금 얼마나 시간/비용이 드는가? (측정값으로)
- 데이터가 있는가?

**산출물**: 아이디어 메모 (1~2 문단)

**→ Gate 0**: AX 포털 제출 → AI 자동 평가 (6차원) → 70점↑ G1/G2 자동 통과 / 그 외 팀장 검토

---

### Phase 1 — 기획 (1~2주)

**목적**: 문제 정의와 솔루션 방향 확정  
**담당**: AX팀 PI + 현업 챔피언  

**이 단계에서 결정하는 것**:
1. **AI 솔루션 유형 선택** (RPA/APA/단독에이전트/멀티에이전트 — 유형분류 기준서 참조)
2. 성공 KPI 정의 (정량 지표로 — "좋아졌다"는 기준 없음)
3. Human-in-the-loop 포인트 정의 (어디서 사람이 검토하는가)
4. 기밀등급 판정 (G1/G2/G3)
5. 데이터 가용성 확인 (있다/없다/수집 필요)

**산출물**: **과제정의서 v0** (아래 §과제정의서 서식 참조)

**→ Gate 1**: 과제정의서 v0 AX팀장 검토 → 설계 착수 승인

---

### Phase 2 — 설계 (1주)

**목적**: 구체적 아키텍처와 구현 계획 수립  
**담당**: AX팀 AI엔지니어 + CDO(데이터 설계)

**이 단계에서 만드는 것**:
- 솔루션 아키텍처 다이어그램
- 데이터 파이프라인 설계 (입력·처리·출력·저장)
- 외부 시스템 연동 목록 및 방식
- Human-in-the-loop 구현 방법
- 개발 일정 (MVP까지)

**산출물**: **과제정의서 v1** (아키텍처 포함) + 구현 계획서

**→ Gate 2**: 설계서 검토 → G3 이면 컴플라이언스 사전 검토 → MVP 착수 승인

---

### Phase 3 — MVP (2~3주)

**목적**: 핵심 기능만 구현하여 가능성 검증  
**담당**: AX팀 AI엔지니어

**MVP 원칙**:
- 전체 기능의 20%로 80%의 가치를 확인
- UI는 최소한, 로직이 돌아가는 것 확인
- 엣지케이스 처리보다 핵심 흐름 동작이 우선

**산출물**: 동작하는 MVP + 내부 테스트 결과 (AX팀 자체)

**→ Gate 3**: AX팀 내부 데모 → 심사 단계 진입 승인

---

### Phase 4 — 심사 (1주)

**목적**: 현업에게 데모하고, 실제로 쓸 것인지 확인받음  
**담당**: AX팀장 + 현업 부서장 + (G3이면 컴플라이언스)

**심사에서 평가하는 것**:
- MVP가 정의한 문제를 실제로 푸는가?
- 현업 챔피언이 파일럿 참여를 공식 확약했는가?
- 예상 KPI가 현실적인가?
- 기밀등급·보안 요건이 설계에 반영되어 있는가?

**심사 결과**:
- 통과 → 파일럿 착수
- 조건부 통과 → 지적 사항 수정 후 재심사 (2주 이내)
- 반려 → 기획 단계 재착수 또는 과제 철수

**산출물**: 심사 결과서 (통과/조건부/반려 + 사유)

**→ Gate 4**: 심사 결과서 서명 → 파일럿 착수 승인

---

### Phase 5 — 파일럿 (4~6주)

**목적**: 실제 현업 업무에서 제한 범위로 운영하며 KPI 실측  
**담당**: AX팀 담당자 + 현업 챔피언 (공동 책임)

**파일럿 운영 규칙**:
- 기존 업무 방식과 병행 (기존 프로세스 대체 금지)
- 2주차에 중간 체크포인트 (AX팀장 보고)
- 이슈 발생 즉시 기록, 종료일 기다리지 않고 즉시 수정

**파일럿 종료 평가**:
- KPI 60% 이상 달성 → 배포 검토
- KPI 60% 미만 → 원인 분석 후 설계 재검토 또는 과제 철수

**산출물**: 파일럿 결과 보고서 (KPI 실측값, 이슈 목록, 현업 피드백)

**→ Gate 5**: 파일럿 결과 보고서 + 현업 부서장 서명 → 배포 승인 요청

---

### Phase 6 — 배포 (1~2주)

**목적**: 전체 배포 및 운영 체계 수립  
**담당**: AX팀 → IT업무개발팀 이관

**배포 체크리스트**:
- [ ] KPI 80% 이상 실측 확인
- [ ] 보안·기밀등급 요건 최종 확인
- [ ] 운영 매뉴얼 작성
- [ ] 모니터링 알림 설정
- [ ] 비상 롤백 절차 문서화
- [ ] 운영팀 인수인계 완료

**운영 이관 원칙**: 안정 운영 단계는 IT업무개발팀이 인수. AX팀은 다음 과제로.

**산출물**: 운영 이관 체크리스트 + 인수인계서

## 과제정의서 서식 (v0 → v1 진화)

### v0 (기획 단계 제출, 1~2페이지)

```
1. 과제명:
2. 신청 부서 / 챔피언 담당자:
3. 해결하려는 문제 (근본 원인):
4. 현재 As-Is (수치로):
   - 처리 시간: ___분/건, ___건/월
   - 오류율: ___%
   - 담당 인원: ___명
5. 기대 To-Be (정량 목표):
   - 목표 처리 시간: ___분/건
   - 목표 오류율: ___%
6. AI 솔루션 유형 (해당 항목 선택):
   [ ] RPA/대시보드  [ ] AI 서비스 활용  [ ] APA  [ ] 단독 에이전트  [ ] 멀티 에이전트
   선택 이유:
7. 데이터 현황:
   - 필요 데이터:
   - 현재 접근 가능 여부: Y / N / 부분
8. 기밀등급: [ ] G1  [ ] G2  [ ] G3
9. Human-in-the-loop 포인트 (AI가 판단하면 안 되는 구간):
```
