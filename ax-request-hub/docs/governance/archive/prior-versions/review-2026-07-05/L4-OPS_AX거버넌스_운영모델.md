## 핵심 원칙: 플랫폼이 통제한다

전통적 거버넌스는 정책 PDF를 만들고 교육한다. 사람이 지키기를 기대한다. AX는 다르다.

**통제는 인프라·데이터·에이전트 3계층에 내장되어, 잘못된 방향은 기술적으로 막힌다.**

---

## 문서 체계 (규정 → 지침 → 가이드라인)

회사 표준 문서 체계를 따른다. 규정이 가장 상위이며, 하위 문서는 규정의 원칙을 구체화한다.

```
┌──────────────────────────────────────────────────────────────┐
│  규정 (전 임직원 준수 의무)                                    │
│  AI 거버넌스 규정 — 큰 틀, 위험 분류, 에이전트 원칙, 금지 사항   │
├──────────────────────────────────────────────────────────────┤
│  지침 (AX팀·현업 부서장·AI CREW 준수)                         │
│  위험등급 통제 / 에이전트 라이프사이클 / 과제 관리 / 비용 자원    │
├──────────────────────────────────────────────────────────────┤
│  가이드라인 (AI CREW·현업 참조)                               │
│  솔루션 유형 선택 / 개발환경 실무 / 에이전트 설계 패턴           │
└──────────────────────────────────────────────────────────────┘
```

## 3계층 기술 통제 구조

```
┌────────────────────────────────────────────────┐
│  Layer 3: 에이전트 계층                         │
│  Kill Switch / Human Checkpoint / 에이전트 ID   │
├────────────────────────────────────────────────┤
│  Layer 2: 데이터 계층                           │
│  Snowflake Horizon 동적 마스킹 / 접근 정책      │
├────────────────────────────────────────────────┤
│  Layer 1: 인프라 계층                           │
│  기밀등급별 라우팅 / G2·G3 네트워크 격리        │
└────────────────────────────────────────────────┘
```

| 레이어 | 현재 상태 | 구현 필요 사항 |
|-------|---------|------------|
| L1 G2·G3 외부 API 차단 | ⚠️ 정책만 | 네트워크 egress 차단 (정보전략팀 협의) |
| L2 Snowflake Horizon 마스킹 | ⚠️ 미착수 | 데이터플랫폼팀 2-track |
| L3 환각 검증 LLM-judge | ⚠️ 미착수 | 리서치 센터 구축 시 |
| L3 Human-in-the-loop 게이트 | ⚠️ 과제별 구현 필요 | 에이전트별 적용 |
| L3 Kill Switch (Circuit Breaker) | ⚠️ 미구현 | 유형 3·4 운영 전 필수 |
