# AX Hub 거버넌스 3축 현황 — 에이전트·데이터·토큰 관리

**작성일**: 2026-08-21
**배경**: AX Hub 거버넌스의 핵심 축을 "에이전트 관리·데이터 관리·토큰 관리" 3축으로 재확인. 각 축의 실제 개발 성숙도를 점검하고 격차 지점을 정리.

---

## 1. 3축 프레임

```
① 에이전트 관리   — Gate1~3, 라이프사이클, KPI, 이의제기
② 데이터 관리     — 카탈로그, 프로비저닝, Gate1 데이터분류, 영향도분석
③ 토큰 관리       — A(엔터프라이즈)/B(AX Hub 자체)/C(배포에이전트) 3트랙
```

이 3축 방향은 회의록 흐름과 일치한다. 초기 회의(§1~5)는 에이전트 축(AI 활용 신청·관리)이 압도적 주제였고, 후반(§6~9)으로 갈수록 토큰 비용 문제가 부상했다. 데이터 축은 처음부터 Gate1 심사·카탈로그 형태로 항상 존재했으나 독립적으로 조명된 적은 없었다.

---

## 2. 축별 성숙도 — 기본 워크플로우 vs 고급 판단 기능

세 축을 공정하게 비교하려면 "기본 CRUD·심사·승인 흐름이 있는가"와 "그 축을 진짜 거버넌스 도구로 만드는 고급 판단 기능이 있는가"를 나눠서 봐야 한다. 전자만 보면 세 축이 비슷해 보이지만, 후자에서 격차가 드러난다.

| 축 | 기본 워크플로우 | 고급 판단 기능 | 격차 |
|---|---|---|---|
| ① 에이전트 관리 | ✅ Gate1~3, 이의제기, GateFail, 라이프사이클 | ✅ KPI 자동 은퇴판정(3개월 연속 미달 → retireFlag), 최근 UI 연결 버그까지 수정 확인 | 없음 — 완결도 높음 |
| ② 데이터 관리 | ✅ 카탈로그 등록·수정, 신청→심사→승인(`dp/requests`), Gate1 데이터분류(Gate1a/1b), 프로비저닝·회수 | ❌ **영향도 질의 엔진 미착수** — "이 데이터 회수 시 몇 개 에이전트가 영향받는가"가 하드코딩 1:1 조회 수준에 머물러 있음 | 다중홉 질의 엔진 하나만 빠짐 |
| ③ 토큰 관리 | 🟡 B·C트랙 코드 완성, A트랙은 API 키 발급 대기 | 🟡 A/B/C 통합 대시보드는 존재하나 A트랙 데이터 소스가 없어 절반만 채워짐 | A트랙 착수만 남음 (인표님 액션 1건) |

---

## 3. 왜 축마다 진도가 다른가 — 원인은 실력이 아니라 세션 배분

세 축의 격차는 설계 역량의 문제가 아니라 **논의에 실제로 할애된 시간**을 그대로 반영한다.

- 에이전트 관리: 워크플로우 설계 v3~v23, 20여 차례 반복 리뷰로 구조적 결함을 전부 걸러냄
- 토큰 관리: A/B/C 트랙 설계, 라우팅 아키텍처 4차 재설계, 구현 리뷰 — 최근 논의의 절반 이상을 차지
- 데이터 관리: 독립적인 리뷰 세션이 배정된 적이 없음 — 항상 다른 두 축의 부수적 언급(Gate1 데이터분류, DataRequest 승인흐름 버그)으로만 등장

**결론**: 데이터 관리는 설계가 안 되어 있어서가 아니라, 영향도 질의 엔진처럼 이미 확정된 우선순위 항목이 독립 세션을 못 받고 계속 밀렸기 때문에 뒤처진 것이다.

---

## 4. 정정 사항 — "데이터 관리 축이 개발 안 됐다"는 진술은 부정확

이전 검토에서 "데이터 관리가 가장 뒤처졌다"고 한 것은 과장이었다. 정확히는:

- 데이터 관리의 **기본 워크플로우는 에이전트 관리와 비슷한 수준으로 이미 구현되어 있다**
- 뒤처진 건 축 전체가 아니라 **영향도 질의 엔진이라는 단일 기능**이다
- 이 기능이 빠져 있으면 데이터 관리가 "기록·승인 시스템"에 머물고, "다른 축(에이전트)에 미치는 영향을 판단하는 거버넌스 도구"로는 아직 작동하지 않는다

---

## 5. 다음 세션 배분 제안

토큰 관리가 최근 몇 세션 만에 설계 전무 상태에서 B·C트랙 실제 코드 완성까지 따라잡은 것처럼, 데이터 관리도 다음 세션 하나를 온전히 배정하면 비슷한 속도로 따라잡을 수 있다.

| 우선순위 | 항목 |
|---|---|
| 1 | 영향도 질의 엔진 (다중홉 — 데이터 회수 시 영향받는 에이전트 N개 배지) |
| 2 | 데이터 카탈로그 노출 강화 (Mulesoft 벤치마킹에서 이미 채택 결정된 항목) |
| 3 | Gate1 데이터분류 심사와 카탈로그 실제 연동 상태 재점검 |

---

## 6. 3축 요약

| 축 | 한 줄 평가 |
|---|---|
| ① 에이전트 관리 | 구조적으로 완결 — 반복 리뷰로 결함을 걸러낸 상태 |
| ② 데이터 관리 | 기본은 완결, 영향도 질의 엔진 한 조각만 남음 |
| ③ 토큰 관리 | 급성장 중 — A트랙 API 키 발급(인표님 액션)만 남으면 완결 |
