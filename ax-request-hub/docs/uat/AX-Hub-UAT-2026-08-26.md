## 시나리오 4 — 데이터 회수(Revoke) 플로우

**대상 역할**: DATA_PLATFORM 또는 AX_TEAM

**관련 파일**: `app/dp/requests/page.tsx`, `app/api/data/requests/[id]/route.ts`

**전제조건**: PROVISIONED 또는 COLLECTING 상태 데이터 요청 1건 이상 존재

| # | 체크 항목 | 기대값 | 결과 | 비고 |
|---|---|---|---|---|
| 4-1 | `/dp/requests` 목록 로드 | 탭(대기중/검토중/완료) + 요청 목록 | ☐ | |
| 4-2 | PROVISIONED 상태 요청 SlideOver 열기 | 상태 드롭다운에 "⚠ 회수 (REVOKED)" 옵션 표시 | ☐ | |
| 4-3 | REQUESTED 상태 요청 | REVOKED 옵션 없음 | ☐ | PROVISIONED/COLLECTING만 가능 |
| 4-4 | REVOKED 선택 시 경고 문구 | "회수 시 연관 에이전트가 자동으로 SUSPENDED 처리됩니다" | ☐ | |

| 4-8 | "회수 확정" 버튼 클릭 | PATCH 성공, 요청 상태 REVOKED로 변경 | ☐ | |
| 4-9 | 회수 후 연관 에이전트 상태 확인 | `/registry`에서 해당 에이전트 SUSPENDED 상태 | ☐ | |

## 통합 테스트 시나리오 — End-to-End 워크플로우

### IT-1: 데이터 신청 → 프로비저닝 → 에이전트 연결 → 회수 전체 사이클

| 단계 | 행동 | 기대값 | 결과 |
|---|---|---|---|
| ① | EMPLOYEE: `/data/catalog`에서 데이터 자산 신청 | DataRequest REQUESTED 생성 | ☐ |
| ② | DATA_PLATFORM: `/dp/requests`에서 REVIEWING → SEC_REVIEW → APPROVED 처리 | DataProvision 생성 | ☐ |
| ③ | DATA_PLATFORM: APPROVED → COLLECTING → PROVISIONED | 상태 전이 완료 | ☐ |
| ④ | AX_TEAM: `/registry`에서 에이전트에 데이터 연결 (AgentDataLink) | DataDepsPanel에 해당 자산 표시 | ☐ |
| ⑤ | DATA_PLATFORM: `/dp/catalog`에서 해당 자산 ImpactBadge 확인 | 에이전트 N개 배지 표시 | ☐ |
| ⑥ | DATA_PLATFORM: `/dp/requests`에서 REVOKED 처리 | RevokeConfirmModal 표시 → 확정 | ☐ |
| ⑦ | AX_TEAM: `/registry`에서 연결됐던 에이전트 상태 확인 | SUSPENDED 상태로 변경됨 | ☐ |
| ⑧ | AX_TEAM: `/governance` 감사 로그 | AGENTS_SUSPENDED_ON_REVOKE 로그 확인 | ☐ |

### IT-2: 과제 신청 → Gate 심사 → 에이전트 등록

| 단계 | 행동 | 기대값 | 결과 |
|---|---|---|---|
| ① | EMPLOYEE: `/chat`에서 과제 신청 | 신청서 초안 생성 → 제출 | ☐ |
| ② | AX_TEAM: `/admin`에서 대기 과제 확인 | 신청 건 대기 큐 표시 | ☐ |
| ③ | AX_TEAM: `/registry`에서 Gate1 심사 | 에이전트 GATE1 단계 등록 | ☐ |
| ④ | AX_TEAM: Gate2 단계 전환 | GATE2로 이동, DataDepsPanel 표시 시작 | ☐ |
| ⑤ | AX_TEAM: `/council`에서 위원회 심의 등록 | 안건 생성 | ☐ |
