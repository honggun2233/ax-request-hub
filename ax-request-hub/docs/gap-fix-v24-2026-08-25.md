## 2. 수정 항목

### ① Prisma 스키마 — Agent ↔ AgentRegistry FK 연결

**파일**: `prisma/schema.prisma`

**문제**: `Agent` 모델과 `AgentRegistry` 모델이 완전히 분리되어 있어
KPI 기록이 어느 모델에 쌓이는지 운연(레코드 생성 시점)에 따라 달라지는 구조였음.
`AgentRegistry.retireFlag` 자동화 로직은 입력이 들어오지 않아 사실상 동작 안 함.

**수정**:
```prisma
model Agent {
  // 기존 필드 ...
  agentRegistryId  String?        @unique
  registry         AgentRegistry? @relation("AgentRegistryLink", fields: [agentRegistryId], references: [id])
}

model AgentRegistry {
  // 기존 필드 ...
  legacyAgent  Agent? @relation("AgentRegistryLink")
}
```

`npx prisma db push` 로 SQLite dev DB 반영 완료.

### ② `/admin/agents` — KPI 기록 버튼 + 모달 추가

**파일**: `app/admin/agents/page.tsx`, `app/api/admin/agents/route.ts`

**문제**: "KPI 기록" 버튼이 레거시 `/api/admin/agents/[id]/kpi-record` 만 호출해
`AgentRegistry.retireFlag` 자동플래그(3개월 연속 60% 미달 → 은퇴 후보) 로직이 영원히 발동 안 됨.

**수정**:
- 에이전트 목록 API 응답에 `agentRegistryId` 포함
- "KPI 기록" 버튼 클릭 시 모달 오픈 (month / achieveRate / note 입력)
- `agentRegistryId` 세팅된 에이전트 → `POST /api/registry/{registryId}/kpi-score` (자동플래그 로직 포함)
- `agentRegistryId` null인 에이전트 → `POST /api/admin/agents/{id}/kpi-record` (레거시 폴백)

**후속 작업**: 기존 Agent 레코드와 AgentRegistry 레코드를 이름 기준으로 매칭해
`agentRegistryId` 백필하는 스크립트 필요 (현재 신규 생성 시에만 세팅).

### ③ `dp/requests` — REVIEWING 전환 엔드포인트 교체

**파일**: `app/dp/requests/page.tsx`

**문제**: APPROVED / REJECTED 전환만 신규 엔드포인트로 교체됐고,
REQUESTED → REVIEWING, REVIEWING → SEC_REVIEW 전환은 역할 체크·감사로그 없는
구형 PATCH `/api/data/requests/{id}` 를 계속 사용.

**수정**:
- REQUESTED → REVIEWING: `POST /api/dp/requests/[id]/review`
- REVIEWING → SEC_REVIEW: `POST /api/dp/requests/[id]/review` (body: `{ secReview: true }`)

두 전환 모두 역할 체크 + 감사로그가 있는 정식 엔드포인트로 통일.
