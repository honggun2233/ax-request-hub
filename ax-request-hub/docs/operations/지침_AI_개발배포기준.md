# AI 개발·배포 기준에 관한 지침

> 문서번호: IT-AX-OPS-004 | 버전: v1.0 | 2026-07-06
> 소관: AX/PI센터 AX팀
> 적용: AX팀·AI CREW (Lv.3)·현업 부서장

---

## 제1장 총칙

### 제1조(목적)

이 지침은 「AI 거버넌스 규정」(IT-AX-REG-001)에서 위임한 사항과 AI 에이전트의 개발·고도화·배포·데이터 연계에 필요한 세부 기준을 정함을 목적으로 한다.

### 제2조(적용 범위)

① 이 지침은 AX팀, AI CREW(Lv.2 이상), 및 데이터플랫폼팀에 적용한다.

② Phase 3 이후의 모든 개발·배포 활동은 이 지침에서 정한 기준을 준수하여야 한다.

### 제3조(용어의 정의)

이 지침에서 사용하는 용어의 정의는 다음과 같다.

① "이관"이란 AI CREW가 개발한 프로토타입을 AX팀에 넘겨 정식 고도화 개발을 위탁하는 절차를 말한다.

② "AX 엔지니어"란 AX팀 소속으로 AI 에이전트의 MVP 이후 고도화 개발을 주도하는 엔지니어를 말한다.

③ "온프레미스"란 사내 서버 환경에서 운영되는 배포 방식을 말한다.

---

## 제2장 AI CREW 개발·고도화 파이프라인

### 제4조(AI CREW 역할 정의)

AI CREW는 현업 부서에서 AI 과제의 초기 탐색과 프로토타입을 담당하는 내부 참여자다.

| 등급 | 역할 | 기대 산출물 |
|------|------|-----------|
| Lv.1 | No-Code 탐색 | AI 활용 아이디어, 도입 제안서 |
| Lv.2 | Low-Code 실험 | 작동 프로토타입 (AX 샌드박스 활용) |
| Lv.3 | Pro-Code 개발 | API 연동·에이전트 초안 (AX팀 협업) |

### 제5조(AX팀 이관 기준 및 개발 역할)

① AI CREW는 PoC·프로토타입 수준까지 개발하고, 이관 기준을 충족하면 AX팀에 인수한다.

② 이관 후 고도화 개발은 AX 엔지니어가 주도한다. AX팀은 판단·승인만 하는 팀이 아니라 고도화 개발과 운영의 직접 담당 주체다.

③ 이관 판정은 다음 3단계로 이루어진다.

| 단계 | 기준 | 판정 방법 |
|------|------|---------|
| 이관 검토 | 프로토타입이 2주 이상 현업에서 반복 사용됨 | AX팀 분기 CREW 리뷰 (초기 등록 후 첫 6개월은 월간) |
| 이관 결정 | 위험등급 中 이상 또는 타 부서 연동 필요 | 자동 평가 점수 70점 이상 |
| 이관 완료 | AX팀이 Agent ID 발급 + 모니터링 설정 완료 | Phase 5 운영 등록 |

### 제6조(이관 전 코드 완성도 기준)

① 이관 시점에 다음 5가지 완성도 요건을 충족하지 않으면 이관을 거부할 수 있다.

| 번호 | 완성도 요건 | 미충족 시 |
|-----|-----------|---------|
| ① | 핵심 기능 로컬 시연 가능 (스크린샷 또는 실시간 데모) | 이관 반려 |
| ② | 입출력 명세 문서화 (입력 포맷·출력 포맷 각 1장 이내) | 이관 반려 |
| ③ | 핵심 코드 GitHub 저장 + README 최소 포함 | 이관 반려 |
| ④ | 기밀 데이터 포함 여부 명시 및 .env 분리 | 이관 반려 |
| ⑤ | 예상 사용자 수·실행 빈도 추정치 제출 | 이관 보류 (AX팀 추정 가능 시 진행) |

② 이관 전까지 AI CREW는 G1 범위 내에서 자율 운용하며, 이관 후에는 AX팀이 오너십과 개발 주도권을 갖는다.

### 제7조(AI CREW 개발 지표)

AI CREW 활동은 다음 6개 지표로 분기별 측정한다.

| 번호 | 지표 | 정의 | 목표 |
|-----|------|------|------|
| ① | 과제 등록 건수 | 분기 중 과제 정의서 제출 건 | 부서당 2건 이상 |
| ② | 프로토타입 완성률 | 등록 과제 중 작동 프로토타입 존재 비율 | 60% 이상 |
| ③ | 이관 전환율 | 프로토타입 중 AX팀 이관 비율 | 30% 이상 |
| ④ | 자동 평가 점수 평균 | 제출 과제의 6차원 평가 평균 | 65점 이상 |
| ⑤ | 현업 활용 지속성 | 이관 후 6개월 이상 운영 유지 비율 | 70% 이상 |
| ⑥ | 운영 장애 발생률 | 에이전트 비정상 종료 건수 / 전체 운영일 | 2% 이하 |

### 제8조(기획 단계 AX 기획자 역할)

① Phase 1 기획 단계에서 AX 기획자는 다음 역할을 수행한다.

1. 과제 정의서 작성 지원: AI CREW가 제출한 아이디어를 구조화된 과제 정의서(v0)로 변환
2. 자동 평가 해석: 6차원 평가 결과를 현업이 이해할 수 있도록 해석·설명
3. 우선순위 조율: 복수 과제 경쟁 시 기술 가능성·비즈니스 임팩트 기준으로 순서 조율
4. 이해관계자 정렬: 현업 부서·AX 엔지니어·컴플라이언스 간 요구사항 갭 식별
5. Phase Gate 관리: 각 Phase 전환 조건 충족 여부 점검 및 진입 승인

② AX 기획자는 과제 정의서 v1 완성 전까지 AI CREW와 최소 1회 리뷰를 수행하여야 한다. Lv.2 이상 CREW는 셀프 리뷰를 인정하되, AX팀 최종 확인은 필수이다.

### 제9조(AX 엔지니어 개발 기준)

Phase 3 MVP 개발 이후 AX 엔지니어는 다음 기준을 반드시 준수한다.

① Agent ID 선발급: 코드 작성 전 AX팀에서 Agent ID를 발급받고 코드에 하드코딩한다.

② 감사 로그 필수: 모든 LLM 호출·도구 실행은 `log_audit()` 함수를 통해 기록한다.

③ Kill Switch 구현: 유형 3·4는 Circuit Breaker 패턴을 필수 구현한다. (가이드라인 제4장 참고)

④ 최소 권한 원칙: 도구는 업무에 필요한 것만 정의하고, 추가 권한은 AX팀 검토 후 부여한다.

⑤ 합성 데이터 선행 검증: G2 이상 실 데이터 사용 전 합성 데이터로 기능 검증을 완료한다.

⑥ PR·코드리뷰 의무: AX팀이 개발 주체이므로 운영 배포 전 AX팀 내 최소 1인 코드리뷰를 통과하여야 한다. Lv.3 CREW가 공동 개발에 참여한 경우 CREW를 추가 리뷰어로 포함할 수 있으나, AX팀 리뷰를 대체할 수 없다. 리뷰 효율화는 표준 리뷰 체크리스트(이관 완성도·보안·KPI 측정 가능성 3항목)를 활용한다.

⑦ 운영 인수 문서: 배포 시 운영 매뉴얼(에이전트 설명, 장애 대응, 롤백 절차)을 작성한다.

## 제3장 배포 환경 결정 기준

### 제10조(배포 환경 유형)

AI 과제의 배포 환경은 기밀등급·운용 특성·인프라 조건에 따라 다음 세 가지 중 하나로 결정한다.

| 환경 | 적용 대상 | 대표 서비스 |
|------|---------|-----------|
| GPT Enterprise | G1, 사내 정형 문서 작업·생산성 도구 | Microsoft Copilot, ChatGPT Enterprise |
| AWS Landing Zone | G1~G2, 대용량 처리·외부 연동·스케일링 필요 | Bedrock(Claude), SageMaker |
| 온프레미스 (사내) | G2·G3, 기밀 운용 데이터·포지션 정보 포함 | 사내 서버, OpenClaw, 내부 API |

### 제11조(배포 환경 결정 기준)

① 배포 환경은 다음 의사결정 기준에 따라 결정한다.

```
데이터에 G3(고객 PI·미공개 운용 포지션)이 포함되는가?
├─ YES → 온프레미스 (외부 전송 절대 금지)
└─ NO  → G2 데이터가 포함되는가?
          ├─ YES → 온프레미스 또는 AWS Bedrock (사내 VPC 내)
          └─ NO  → 대용량 처리 또는 외부 API 연동이 필요한가?
                    ├─ YES → AWS Landing Zone
                    └─ NO  → 생산성·협업 도구 성격인가?
                               ├─ YES → GPT Enterprise
                               └─ NO  → AWS Landing Zone 또는 온프레미스
```

② 다음 각 호의 추가 조건을 준수하여야 한다.

1. 실시간 운용 의사결정(주문·리밸런싱 판단)이 포함되면 온프레미스를 우선한다.
2. 외부 규제 신고(공시·보고서 제출) 데이터가 포함되면 컴플라이언스팀 사전 승인을 받아야 한다.
3. AWS Landing Zone 사용 시 AI데이터플랫폼팀과 VPC 피어링·IAM 정책을 협의하여야 한다.

## 제4장 데이터플랫폼팀 연계

### 제12조(협업 원칙)

AI 과제가 데이터플랫폼팀 소관 데이터 소스(DW, Mart, 실시간 피드)를 사용할 경우, 다음 원칙을 따른다.

① 선협의 원칙: 데이터 소스 결정 전 데이터플랫폼팀과 가용성·SLA·기밀등급을 확인한다.

② 계약 기반 접근: 비공식 직접 연결을 금지한다. 데이터 요청서 → 검토 → 접근 권한 부여 순서를 준수한다.

③ CDO 카탈로그 등록: 사용하는 데이터 소스는 CDO 데이터 카탈로그에 등록 후 사용한다.

④ SLA 준수: 데이터 신선도(T+1, T+0 등) 요건은 과제 정의서에 명시하고 데이터플랫폼팀의 확인을 받아야 한다.

### 제13조(데이터 요청 표준)

AX팀이 데이터플랫폼팀에 데이터 접근을 요청할 때 다음 정보를 제공한다.

| 항목 | 내용 |
|------|------|
| 과제명 / Agent ID | AX 과제명, 발급된 Agent ID |
| 요청 데이터 | 데이터셋명, 테이블/컬럼 범위 |
| 사용 목적 | 어떤 AI 기능에 사용하는지 1~2줄 |
| 기밀등급 | 요청 데이터의 등급 (G1/G2/G3) |
| 접근 방식 | API 호출 / 배치 추출 / 스트리밍 |
| 갱신 주기 | 실시간 / 일 1회 / 주기 없음 |
| 사용 기간 | 프로젝트 종료일 또는 상시 |

### 제14조(데이터 플로우 문서화 기준)

① 데이터플랫폼팀 연계가 포함된 과제는 다음 흐름을 과제 정의서에 다이어그램으로 포함하여야 한다.

```
[데이터 원천]
  └─ 데이터플랫폼팀 DW/Mart
       └─ (API 또는 배치 추출)
            └─ AX 과제 수신 레이어 (기밀등급 경계 표시)
                 └─ AI 모델/에이전트 처리
                      └─ 산출물 (결과 저장·전달 방식)
                           └─ (G2 이상이면 온프레미스 내부에서만 유통)
```

② 문서화 시 다음 항목을 반드시 포함하여야 한다.

1. 데이터 흐름의 각 단계에서 기밀등급 명시
2. G2 경계를 넘는 지점 표시 (외부 전송 금지 경계)
3. 비정상 데이터 수신 시 처리 방법 (폴백·알림·중단)
4. 데이터플랫폼팀 SLA 위반 시 에이전트 동작 정의
