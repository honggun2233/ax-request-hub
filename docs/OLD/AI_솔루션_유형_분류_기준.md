> 문서번호: IT-AX-TYPE-001  
> 버전: v1.0 | 작성: IT업무개발팀 AX/PI팀 | 2026-07-02  
> **이 문서를 읽어야 하는 사람**: 과제를 신청하는 현업 담당자, AI 솔루션을 설계하는 AX팀원

---

## 핵심 원칙

> **"AI agent가 항상 정답은 아니다."**  
> 복잡한 Agent 시스템보다 단순한 RPA나 대시보드가 더 빠르고 안정적인 케이스가 많다.  
> 도구는 문제에 맞춰 선택하는 것이지, 유행을 따르는 것이 아니다.

---

## 1. 솔루션 유형 5가지

### 유형 0 — RPA / 대시보드 (자동화·시각화)

**정의**: AI 없이 규칙 기반 자동화 또는 데이터 시각화  
**특징**: 예측 가능, 빠름, 유지보수 쉬움, AI 불필요

| 하위 유형 | 설명 | 예시 |
|-----------|------|------|
| RPA | 반복 클릭·입력 자동화, 규칙 기반 데이터 이동 | 시스템 간 데이터 복사, 정기 보고서 생성 |
| 대시보드 | 데이터 집계·시각화, 알림 | KPI 모니터링, 이상 감지 알림 |

**언제 선택하나**: 판단이 필요 없는 반복 작업, 규칙이 명확한 프로세스

---

### 유형 1 — AI 서비스 활용 (임직원 직접 사용)

**정의**: 임직원이 기성 AI 도구(Claude, ChatGPT 등)를 대화 형식으로 직접 사용  
**특징**: 자동화 없음, 사람이 매번 지시하고 결과 판단, 구현 없음

| 케이스 | 설명 | 허용 등급 |
|--------|------|---------|
| 문서 요약·번역 | 공개 문서 처리 | G1 |
| 보고서 초안 | 사내 정보 활용 주의 | G1 |
| 코드 검토 | 민감 코드 제외 | G1 |
| G2 업무 활용 | 사내 AI 시스템만 | G2 |

**언제 선택하나**: 1회성 작업, 자동화까지는 필요 없는 업무, 개인 생산성

---

### 유형 2 — APA (AI-Powered Automation, AI 강화 자동화)

**정의**: 고정된 워크플로우에서 특정 단계만 AI가 판단하는 자동화  
**특징**: 워크플로우가 미리 정해져 있음, AI는 규칙 대신 판단하는 부분에만 개입

**RPA와 APA의 차이**:
```
RPA: 입력 → [규칙 판단] → 출력   (분기가 if/else로 미리 정해짐)
APA: 입력 → [AI 판단]  → 출력   (분기를 AI가 맥락에 따라 결정)
```

| 케이스 | AI 개입 부분 | 나머지 |
|--------|------------|-------|
| 공시 자동 분류 | 문서 유형 판단 (AI) | 수신·저장·알림은 규칙 (자동) |
| 계약서 위험도 스크리닝 | 조항 위험 판단 (AI) | 수신·결과 저장·담당자 통보 (자동) |
| ETF 리포트 요약 배포 | 요약 생성 (AI) | 수신·배포는 스케줄러 (자동) |

**언제 선택하나**: 워크플로우는 정해져 있는데 중간에 AI 판단이 필요한 한두 단계가 있을 때

---

### 유형 3 — 단독 에이전트 (Single Agent)

**정의**: 목표가 주어지면 에이전트가 자율적으로 툴을 사용하며 목표 달성  
**특징**: 자율성 있음, 툴 사용, Human-in-the-loop 구간 포함

**APA와 Agent의 차이**:
```
APA:   입력 → 고정 단계 A → AI 판단 → 고정 단계 B → 출력
Agent: 입력 → [자율 계획 수립] → [필요한 툴 선택·실행] → [결과 평가·반복] → 출력
```

| 케이스 | 에이전트 자율 행동 |
|--------|-----------------|
| 리서치 어시스턴트 | 공시·리포트 검색, 요약, 교차 검증, 출처 부착 |
| 코드 리뷰 에이전트 | 코드 분석, 테스트 실행, 리뷰 코멘트 생성 |
| 과제 평가 에이전트 | 신청서 분석, 6차원 점수 산출, 근거 작성 |

**언제 선택하나**: 순서가 유동적이고, 중간 결과에 따라 다음 단계가 달라지는 작업

---

### 유형 4 — 멀티 에이전트 (Multi-Agent)

**정의**: 전문화된 에이전트들이 역할 분담·협업하여 복잡한 목표 달성  
**특징**: 높은 자율성, 조율 에이전트(오케스트레이터) 필요, 복잡도 높음

| 케이스 | 에이전트 구성 |
|--------|------------|
| ETF 운용 시뮬레이션 | 상품개발 AI + 운용역 AI + 리스크 관리 AI |
| AX 거버넌스 팀 | Jarvis(오케스트레이터) + CTO + CFO + CDO + ... |
| AI 신상품 파이프라인 | 테마발굴 AI + 인덱스설계 AI + 검증 AI + 출시문서 AI |

**주의**: 멀티에이전트는 구축·디버깅·유지보수 비용이 높다. 단독 에이전트로 해결 가능하면 단독 에이전트를 쓴다.

**언제 선택하나**: 전문성이 다른 여러 역할이 병렬·협업해야 하는 복잡한 목표

## 2. 유형 선택 의사결정 트리

```
과제가 들어왔을 때:

Q1. 반복되는 작업인가?
  └─ No → AI 서비스 활용 (유형 1) 우선 검토
  └─ Yes ↓

Q2. AI 판단 없이 규칙만으로 자동화 가능한가?
  └─ Yes → RPA / 대시보드 (유형 0)
  └─ No ↓

Q3. 워크플로우(순서)가 미리 고정되어 있는가?
  └─ Yes → APA (유형 2)
  └─ No ↓

Q4. 자율적으로 계획하고 툴을 선택해야 하는가?
  └─ Yes ↓

Q5. 전문 역할이 다른 여러 에이전트가 필요한가?
  └─ No → 단독 에이전트 (유형 3)
  └─ Yes → 멀티 에이전트 (유형 4)
```

**복잡할수록 좋은 게 아니다.** 유형 0이나 1로 해결되면 그게 정답이다.
