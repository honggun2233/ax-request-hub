## AX팀이 존재하는 이유

> "도입을 늦추지 않으면서, 가드레일을 함께 깔며, 현업과 AI를 '일하게' 만드는 팀."  
> — AX팀 출범 청사진 v0.5

**빠른 도입**과 **안전한 통제**는 둘 중 하나를 선택하는 것이 아니다. 병행이 원칙이다.

### 4대 운영 원칙

| 원칙 | 의미 | 실패 패턴 |
|------|------|-----------|
| **속도 우선** | governance-first로 도입을 막지 않는다 | "가드레일 다 깔고 시작하자" |
| **등대 우선** | 1~2개 핵심 과제를 완주하여 신뢰를 쌓는다 | "여러 과제 동시에 시작하자" |
| **현업 주도** | 현업이 요구하고 검증한다. AI팀이 대신 판단하지 않는다 | "AX팀이 알아서 해줄 거야" |
| **측정 가능** | ROI와 품질 지표로 증명한다. 느낌으로 평가하지 않는다 | "써보니 좋은 것 같아요" |

## 1. 팀 구조와 R&R

### 1.1 AX/PI팀 역할 분담

| 역할 | 담당 업무 |
|------|---------|
| **PI / 과제기획** | 현업 인터뷰, 과제 발굴·기획, 과제 신청 상담, 파일럿 결과 평가 |
| **AI 엔지니어** | PoC·파일럿 구현, 에이전트 개발, AX 포털 운영 |
| **데이터 / 평가** | 데이터 파이프라인 설계, CDO 협업, RAG 품질 평가 |
| **거버넌스** | 감사 로그 운영, 기밀등급 판정, 컴플라이언스 협의, 정책 개정 |

> 초기에는 겸무. 과제 수가 늘어나면 역할 전담으로 분화.

### 1.2 AX팀이 하는 것 vs 하지 않는 것

**하는 것**
- 과제 발굴 → PoC → 파일럿 → 운영 승격 지원
- 에이전트 개발 "paved road" 제공 (재사용 가능한 패턴)
- 기밀등급 판정 및 거버넌스 통제 운영
- 데이터플랫폼팀과 2-track 협업

**하지 않는 것**
- AI 사용 여부를 현업 대신 결정 (현업이 결정, AX는 지원)
- 운영 단계 시스템 유지보수 (IT업무개발팀으로 이관)
- 소프트웨어 개발 외주 발주 결정 (별도 프로세스)
- 규제·법규 해석 (컴플라이언스팀 권한)

## 2. 100일 로드맵

출범 후 100일 이내에 4단계를 완주한다.

| 단계 | 기간 | 목표 | 산출물 |
|------|------|------|-------|
| **0: 인벤토리** | 1~2주 | 전사 AI 활용 현황 파악 | 부서별 AI 활용 인벤토리 |
| **1: 등대 PoC** | 3~6주 | 핵심 2개 과제 PoC 완료 | PoC 결과 보고서 + ROI 초안 |
| **2: 가드레일 v0** | 병행 | 기밀등급 매트릭스·플랫폼 통제 기반 | 거버넌스 운영모델 v0.1 + AI 사용정책 v0 |
| **3: 데이터플랫폼 협의** | 6주 이후 | Snowflake 2-track 착수 합의 | 데이터플랫폼 협업 RACI |

> ★ **등대 과제 (현재 확정)**: 리서치 어시스턴트 RAG [G2] — 공시·리포트·뉴스 검색, 출처 강제, 환각 검증

## 3. 과제 운영 사이클 (PoC → 파일럿 → 운영)

### 3.1 흐름

```
[발굴·신청] → [AI 평가] → [PoC (2주)] → [파일럿 (6주)] → [운영 승격] → [모니터링]
                                ↑                ↑                ↑
                           AX팀장 승인      팀장+현업부서장     IT담당임원
```

### 3.2 단계별 기준

| 단계 | 기간 | 진입 기준 | 승격 기준 | 승인자 |
|------|------|-----------|-----------|-------|
| **PoC 착수** | 2주 | AI 평가 70점↑ + G1/G2 → 자동<br>그 외 → 팀장 검토 | 기술 실현 가능성 + 데이터 가용성 확인 | AX팀장 |
| **파일럿 전환** | 6주 | PoC 성공 + 현업 챔피언 지정 | KPI 60%↑ + 현업 사용률 유지 | AX팀장 + 현업부서장 |
| **운영 승격** | — | 파일럿 완료 | KPI 80%↑ + 사고 0건 + 근거문서 완비 | IT솔루션담당 임원 |

> **경계 구간 (68~72점)**: 자동 처리 금지. AX팀장 직접 검토.

### 3.3 PoC 빠른 실패 원칙
- 2주 이내에 실현 가능성을 확인한다
- PoC에서 막히면 과감하게 중단하고 다음 과제로 이동한다
- PoC 실패도 기록하여 향후 유사 과제의 판단 자료로 쓴다

## 4. 과제 AI 자동 평가 (6차원, 100점)

| 차원 | 배점 | 평가 기준 | 고배점 조건 |
|------|------|-----------|-----------|
| 임팩트 | 25 | 영향 인원, 빈도, 전략 정합성 | 전사 50명↑, 매일 반복 |
| ROI | 25 | 시간·비용 절감, 수익 기여 | 연 500시간 절감 or 오류율 50%↓ |
| 기밀등급 | 15 | 처리 복잡도 반영 | G1 = 15점, G2 = 10점, G3 = 5점 |
| 난이도 역산 | 15 | 빠른 성과 우선 | 난이도 낮을수록 고배점 |
| 현업 준비도 | 10 | 데이터 가용성, 챔피언 유무 | 데이터 즉시 제공 + 챔피언 지정 |
| 전략 정합성 | 10 | 등대 과제·100일 로드맵 연관 | 리서치 어시스턴트·ETF 과제 |

## 5. 과제 신청 접수 (창구 구성 검토 중)

현업이 AI 과제를 신청하고 AX팀이 접수·평가하는 창구 방식은 현재 검토 중이다. 확정 전까지 과제 신청은 **AX팀장에게 직접 연락** 또는 **구두·이메일 접수** 방식으로 운영한다.

### 5.1 현행 접수 절차 (창구 미정 운영 기준)
1. 현업 AI CREW → AX팀 담당자에게 과제 아이디어 전달
2. AX팀 담당자 → 과제 정의서 v0 작성 지원
3. AX팀장 → 스코어카드(6차원) 평가 후 결과 통보 (위험등급별 기한: G1 5일 / G2 10일 / G3 15일)
4. AX팀 내부 인벤토리에 등록 (Phase 1 기획 개시)

## 6. 데이터플랫폼팀 2-track 협업

AX의 거버넌스와 데이터플랫폼은 분리된 트랙이지만 긴밀히 연결되어야 한다.

| Track | AX/PI팀 역할 | 데이터플랫폼팀 역할 |
|-------|------------|----------------|
| **AI 활용 가드레일** | G1/G2/G3 기준 정의, 허용 모델 목록 관리 | Snowflake Horizon 마스킹·접근정책 구현 |
| **RAG 데이터 소싱** | 리서치 어시스턴트 요건 정의, 품질 기준 | DART·KRX 파이프라인 구축, Cortex Search 운영 |

**협업 원칙**: AX가 요건을 정의하면 데이터플랫폼이 구현한다. 역할이 뒤집히면 안 된다.

## 9. FAQ

**Q. 신청 후 얼마나 기다려야 하나요?**  
AI 자동 평가 결과는 2분 이내 이메일로 전달됩니다. 팀장 검토 대상이면 5영업일 이내 추가 결과를 받습니다.

**Q. 반려된 과제는 재신청 가능한가요?**  
피드백 반영 후 언제든지 재신청 가능합니다.

**Q. G3 기밀 데이터를 써야 하는데 어떻게 하나요?**  
AX팀 + 컴플라이언스 사전 협의 필수입니다. G3는 온프레미스 환경에서만 처리하며, 외부 AI 서비스 입력은 기술적으로 차단됩니다. (거버넌스 운영모델 1.1 Layer 1 참조)

**Q. ChatGPT 등 외부 AI 도구를 쓰면 안 되나요?**  
G1(일반정보) 업무는 자유롭게 사용 가능합니다. G2·G3 데이터 입력은 금지입니다. 구분이 헷갈리면 AX팀에 문의하세요.

**Q. 이미 비공식으로 AI를 쓰고 있는데 신고해야 하나요?**  
'신고' 개념이 아닙니다. AX 포털에 등록해서 공식 지원을 받으세요. 잘 되고 있다면 PoC 통과로 인정받을 수 있습니다.
