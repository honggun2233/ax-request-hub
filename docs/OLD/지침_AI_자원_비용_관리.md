## 1. 자원 관리 원칙

1. **중앙 관리**: API 키·모델 접근 권한은 AX팀이 중앙 관리. 현업 개인 발급 금지.
2. **과제 단위 추적**: 비용은 Agent ID에 귀속. 부서 전체 비용이 아니라 과제별로 추적.
3. **단계별 한도**: 개발 < 파일럿 < 운영. 단계를 넘는 사용 불가.
4. **초과 알림**: 한도 80% → 자동 알림. 100% → 자동 정지 또는 팀장 긴급 승인.

## 3. API 키 관리 정책

### 3-1. 개인이 절대 하면 안 되는 것

- 개인 카드로 ChatGPT Plus·Claude Pro 등 AI 서비스 가입 후 업무 사용 → 사용 기록 없음, 기밀 유출 위험
- 개인 계정으로 API 키 발급 → 비용 추적 불가, 보안 위반
- 팀 공용 API 키를 코드에 하드코딩 → 키 유출 시 전체 피해
- AX팀 미등록 에이전트에 키 사용 → 관리 불가

### 3-2. 올바른 API 키 발급 절차

```
AI CREW → AX팀에 키 신청 (과제 ID + 용도 + 예상 사용량)
       → AX팀장 승인 (한도 배정 포함)
       → AX팀이 환경변수 또는 Vault로 키 전달 (코드에 직접 넣지 않음)
       → 사용량 모니터링 자동 시작
```

### 3-3. 키 보관 규칙

- 로컬 개발: `.env` 파일에만 저장 (`.gitignore` 필수)
- 서버 배포: 환경변수 주입 (Vercel Env, Docker Secret 등)
- **`.env` 파일을 GitHub에 올리면 즉시 키 무효화 + 경고 처리**
- 공유 폴더·이메일·메신저로 API 키 전달 금지

### 3-4. 키 종류별 관리 주체

| 키 종류 | 관리 주체 | 비고 |
|-------|---------|------|
| Anthropic (Claude) API | AX팀 중앙 관리 | 과제별 분리 발급 |
| OpenAI (GPT) API | AX팀 중앙 관리 | G1 한정 |
| Google Gemini API | AX팀 중앙 관리 | G1 한정 |
| 사내 Bedrock 접근 키 | AX팀 + 인프라팀 공동 | G2용 (구축 후) |
| 외부 데이터 API (DART, KRX 등) | AX팀 중앙 관리 | 과제별 분리 |

### 4-2. 한도 초과 프로세스

```
사용량 80% 도달 → AX팀 + AI CREW 자동 알림
사용량 100% 도달 → 에이전트 자동 일시정지
                  → 업무 중단이 발생하면: 팀장 긴급 승인 루트 (2시간 내)
                  → 일반 초과: 다음달 정산 후 한도 조정 검토
월말 → 과제별 비용 정산 리포트 → AX팀장 보고
```

### 4-3. 모델별 비용 특성 (2026-07 기준)

| 모델 | 비용 수준 | 적합 용도 | 권장 |
|------|---------|---------|------|
| claude-haiku-4-5 | 저렴 | 대량 분류, 단순 요약, 라우팅 | 유형 2 APA 대량 처리 |
| claude-sonnet-4-6 | 중간 | 일반 업무 에이전트, 문서 요약 | **현재 주력 모델** |
| claude-opus-4-8 | 고가 | 복잡한 추론, 핵심 의사결정 | 고위험 업무 검증에만 |
| GPT-4o | 중간 | Google 생태계 연동, Copilot | G1 일반 업무 |

**비용 절감 원칙:**
- 단순 분류·라우팅 → Haiku 먼저 시도
- RAG 기반 응답 → 검색은 임베딩 비용, 요약만 LLM 비용
- 동일 프롬프트 반복 → Prompt Cache로 비용 절감 (50~90% 절감 가능)
- 실시간이 아닌 업무 → Batch API 활용 (비용 50% 절감)
- 출력 토큰 최소화 → 프롬프트에 "간결하게 답변" 지시
