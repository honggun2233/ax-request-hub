## 금번 업데이트 핵심 (v0.5에서 추가·변경된 내용)

### 1. AX팀-현업 역할 구분 명확화 (지침 제13장 신설)

기존에 여러 장에 흩어져 있던 역할 정의를 **R&R 매트릭스 + 역할 흐름도**로 통합.

- **과제 신청·처리 기준 역할 흐름**: 신청 → 스코어카드 → Phase Gate → UAT → 운영까지 단계별 누가 무엇을 하는지 도식화
- **Phase별 R&R 매트릭스**: Phase 0~6 각 단계에서 현업/AX팀/협조 부서 역할 일람표
- **에스컬레이션 기준표**: G3/경계구간/위원회 상정 조건 명시

### 2. AI 개발 플로우 추가조항 (AX_AI개발플로우_추가조항.md 신규)

- AI CREW 개발 범위 및 AX팀 인수 기준 (완료 조건 5가지)
- 배포 환경 의사결정 기준 (결정 트리: GPT Enterprise / AWS / 온프레미스)
- 데이터플랫폼팀 연계 플로우 (크루 직접 연동 금지 원칙)

### 3. Agent ID·라이프사이클 Alignment (지침 제7장 전면 개편)

기존에 분리되어 있던 Phase Gate(제2장)·Agent ID(제7장)·데이터플랫폼팀(제12장)을 **두 라이프사이클 관점**으로 통합.

- **생성 라이프사이클**: Phase 0~6 각 단계에서 ID 상태·에이전트 상태·데이터 접근·AX팀/데이터플랫폼팀 역할을 단일 매핑 테이블로 정리
- **관리 라이프사이클**: 🟡→🟢→🔵→🔴 상태 전환 조건, 각 상태에서 AX팀/데이터플랫폼팀 역할 구분 명확화
- **Phase·ID·상태 전체 매핑**: 두 라이프사이클 교차점(Phase 5 파일럿) 명시
- **임시 ID 도입**: 파일럿 단계 `AX-DEV-` 임시 ID → 운영 전환 시 정식 ID로 교체

### 4. 우수 에이전트 선정 기준 구체화 (지침 제14장 보강)

5개 기준에 **측정 방법·데이터 소스·사전 합의 항목** 추가.

- **핵심 원칙**: 과제 정의서 v1에 목표값 사전 합의한 지표만 유효. 미합의 시 해당 기준 0점
- KPI 달성률: 감사 로그 자동 집계 / ROI: 현업 부서장 확인 서명
- 분기 심사 대상: 🟢 Active 90일 이상 유지 에이전트만
- **탁월 에이전트(90점↑)**: AX Excellence 별도 표창, 성과 인센티브 연계(HR 협의)

### 5. AX팀 개발 주체 및 이관 기준 명확화 (지침 v7.4~v7.5)

- 제22조: AX팀 코드리뷰 필수 (Lv.3 CREW는 추가 리뷰어만, 대체 불가)
- 제19조: CREW 이관 전 완성도 5항목 신설 — 미충족 시 이관 반려 가능

### 6. AI Native 원칙 및 암묵지 데이터화 성숙도 평가 (규정 v6.3, 지침 v7.6~v7.7)

- 규정 제3조: "토큰을 소비하되 조직 지식이 누적되지 않는 사용은 AI 투자로 보지 않는다" 원칙 신설
- 지침 제8장: 암묵지 데이터화 성숙도 평가 3차원 신설
  - 차원 1 (지식 포착): 과제 정의서·프롬프트 문서화·감사로그·실패 리뷰 [분기/정량]
  - 차원 2 (활용·재사용): Caching 적용률·이관 재작업률·과거 사례 참조 [반기/정량]
  - 차원 3 (조직 역량): 온보딩 기간·이탈 연속성·에이전트 자립도 [반기/정성]

## 검토 요청 포인트

### 규정 (REG-001)
- [ ] 제3조 AI Native 원칙 — "조직 지식 누적 없는 사용은 AI 투자 아님" 표현 수위 적절한지
- [ ] 제6조 위험 분류 기준 — 투자·운용 업무 적용 시 위험등급 판단 논란 여지 없는지
- [ ] AI 에이전트 유형 4가지 정의 — 현업 업무에 맞는 분류인지

### 지침 (OPS-002)
- [ ] **제13장 R&R 매트릭스** — 현업 역할과 AX팀 역할 경계선이 실무에서 작동 가능한지
- [ ] **제19조 이관 완성도 5항목** — 현업 CREW가 충족 가능한 수준인지 (너무 높으면 이관 기피)
- [ ] **제8장 암묵지 평가 3차원** — 차원 1 미달 시 과제 등록 상한 1건 제한이 과도하진 않은지
- [ ] **제14장 우수 에이전트 보상** — 80점 커트라인 적절성, HR·경영기획 연계 실현 가능성
- [ ] Phase 0~6 단계 전환 기준 — 실제 프로젝트에 적용 시 모호한 구간 없는지

### 가이드라인 (GUIDE-003)
- [ ] Kill Switch 구현 예시 — 실제 코드베이스에 적용 가능한 수준인지
- [ ] 감사 로그 필드 정의 — 법적 요건(금융감독원 AI RMF) 충족 여부

### 운영방안_AX위원회
- [ ] 위원회 구성원 범위 — IT 이외 부서(준법·운용·경영기획) 포함 여부
- [ ] 정기·임시 회의 주기 — 과제 수가 늘어날 경우 운영 부담 최소화 방안
