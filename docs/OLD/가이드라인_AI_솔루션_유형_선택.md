## 1. 왜 유형 분류가 필요한가?

현업에서 AI를 도입하려 할 때 가장 많이 발생하는 오해:

> "AI를 쓰면 다 에이전트 아닌가요?"

그렇지 않다. AI의 자율성 수준에 따라 개발 복잡도·비용·위험·거버넌스 요건이 완전히 달라진다. **업무에 맞는 유형을 선택하는 것이 과제의 성패를 결정한다.**

---

## 2. AI 솔루션 5가지 유형 (유형 0~4)

### 유형 0 — RPA·대시보드 (규칙 기반 자동화)

```
입력 → [규칙 판단] → 출력
       AI 판단 없음
```

- **특징**: 정해진 규칙대로 반복 처리. AI 판단·학습 없음.
- **장점**: 예측 가능, 빠른 구현, 낮은 비용, 규제 리스크 없음
- **단점**: 규칙 밖의 예외 처리 불가, 규칙 변경 시 수작업 필요
- **적합 케이스**: 정형 데이터 추출, 보고서 자동 생성, 데이터 포맷 변환, KPI 대시보드

> **AI가 반드시 필요하지 않을 수 있다.** 단순 반복 업무라면 RPA가 더 안정적이고 저렴하다.

---

### 유형 1 — AI 서비스 활용 (개인 직접 사용)

```
사람 → [AI 서비스] → 사람이 검토·사용
      (ChatGPT, Claude 등)
```

- **특징**: 임직원이 직접 AI 서비스를 사용. 자동화 없음.
- **장점**: 즉시 시작, 별도 개발 불필요, 유연성 높음
- **단점**: 비용 추적 어려움, 일관성 없음, G2·G3 데이터 사용 불가
- **적합 케이스**: 문서 요약, 번역, 아이디어 탐색, 코드 작성 지원, 회의록

> **G1 데이터만 사용** 가능. 사내 데이터·고객 정보 절대 입력 금지.

---

### 유형 2 — APA (AI 자동화 파이프라인)

```
입력 → [AI 판단 Step 1] → [처리] → [AI 판단 Step 2] → 결과
       각 단계에 사람 승인 포인트 포함
```

- **특징**: AI가 다단계 워크플로를 자동 처리. 사람 승인 포인트 있음.
- **장점**: 반복 업무 자동화, 일관성, 비용 절감 효과
- **단점**: 개발 필요, AX팀 과제 등록 의무, 모니터링 필요
- **적합 케이스**: 공시 자동 분류, 이상 탐지 알림, 리포트 초안 자동 생성, 문서 분류·태깅

> **RPA와의 차이**: RPA는 규칙으로 판단, APA는 AI가 판단 (예: 문서 내용을 읽고 카테고리 분류)

---

### 유형 3 — 단독 에이전트

```
목표 입력 → [에이전트: 계획 수립]
              → [Tool 1 호출] → 결과 분석
              → [Tool 2 호출] → 결과 분석
              → [최종 판단·출력]
```

- **특징**: AI가 목표를 받아 스스로 계획을 세우고 도구를 자율 호출.
- **장점**: 복잡한 다단계 작업 자동화, 유연성
- **단점**: 예측 불가 행동 가능성, 높은 개발·운영 복잡도, 중위험 이상 분류
- **적합 케이스**: 리서치 에이전트, 데이터 수집 에이전트, 코드 리뷰 에이전트

> **반드시 AX팀 과제 등록 + Agent ID 발급 필요.**

---

### 유형 4 — 멀티 에이전트

```
오케스트레이터 에이전트
  ├── 에이전트 A (운용 분석)
  ├── 에이전트 B (리스크 평가)
  └── 에이전트 C (리포트 생성)
  → 종합 결과
```

- **특징**: 여러 에이전트가 역할을 나눠 협업. 복잡한 멀티스텝 업무.
- **장점**: 대규모 복잡 업무 처리 가능
- **단점**: 가장 높은 개발 복잡도, 오류 전파 위험, 임원 사전 승인 필요
- **적합 케이스**: 운용·리서치·리스크 통합 분석, 복합 고객 리포트 자동화

## 3. 의사결정 트리 (유형 선택 흐름)

```
업무 자동화를 고려하는가?
│
├─ NO → 유형 1 (AI 서비스 직접 활용)
│
└─ YES → AI의 판단·학습이 필요한가?
           │
           ├─ NO → 유형 0 (RPA·대시보드)
           │
           └─ YES → 자동화가 반복·스케줄 기반인가?
                      │
                      ├─ NO → 유형 1 (직접 사용)
                      │
                      └─ YES → 에이전트가 스스로 계획을 세우는가?
                                 │
                                 ├─ NO → 유형 2 (APA)
                                 │
                                 └─ YES → 여러 에이전트가 협업하는가?
                                            │
                                            ├─ NO → 유형 3 (단독 에이전트)
                                            │
                                            └─ YES → 유형 4 (멀티 에이전트)
```

## 5. 잘못된 유형 선택 사례

**Case 1: RPA가 맞는데 에이전트로 만든 경우**
> "공시 날짜 추출 자동화에 GPT-4o + 에이전트를 썼는데 비용이 너무 많이 나왔어요"
→ 정형 데이터 추출은 규칙 기반 파싱(유형 0)이 더 빠르고 정확하고 저렴하다.

**Case 2: 유형 1로 충분한데 복잡한 APA를 개발한 경우**
> "회의록 요약을 APA로 만들었는데 개발에 한 달이 걸렸어요"
→ 임직원이 Claude.ai를 직접 사용하면 되는 업무였다. 개발 자원 낭비.

**Case 3: 고위험 업무에 에이전트를 Human-in-the-loop 없이 적용한 경우**
> "리밸런싱 에이전트가 자동으로 주문을 냈는데 잘못된 종목에 들어갔어요"
→ 고위험 업무에는 에이전트 단독 실행이 금지된다. 사람 이중 승인 필수.
