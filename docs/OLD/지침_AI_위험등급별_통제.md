## 1. 위험등급 결정 프로세스

과제 신청 시 아래 4단계로 위험등급을 결정한다.

```
Step 1. 업무 분류 확인
        → 규정 제5조 고/중/저위험 업무 목록 대조

Step 2. 데이터 기밀등급 확인
        → G3 포함 시 → 고위험 자동 상향
        → G2만 포함 시 → 최소 중위험

Step 3. 처리 유형 확인
        → 유형 3·4 (자율 에이전트) → 최소 중위험
        → 고위험 업무에 유형 3·4 → 고위험

Step 4. 영향 범위 확인
        → 고객 자산·계약 영향 → 고위험 자동 상향
        → 내부 업무만 → 현 등급 유지
```

> **원칙**: 등급이 애매한 경우 상위 등급으로 분류한다. AX팀 판단이 필요하면 사전 문의.

## 2. 고위험 업무 통제 요건

### 2-1. 적용 업무 (전체 목록)

| 업무 분류 | 세부 업무 |
|---------|---------|
| 투자·운용 의사결정 | ETF 리밸런싱 실행, 주문 집행, 포지션 변경, NAV 확정 |
| 신용·위험 평가 | 신용등급 산출, VaR 계산, 모델 위험 평가, 스트레스 테스트 |
| AML·FDS | 이상거래 탐지 최종 판정, 자금세탁 의심거래 확정 |
| 공시·법정문서 생성 | 투자설명서, 약관, 집합투자규약, 금감원 제출 서류 |
| 컴플라이언스 판정 | 규정 위반 여부 확정, 제재 수위 판정 |
| 고객 계약·실행 | 투자일임 계약, 고객 자산 이동 지시, 고객 고지 발송 |

### 2-2. 필수 통제 요건

| 통제 항목 | 요건 |
|---------|------|
| **Human-in-the-loop** | AI 산출물 → 반드시 담당자 + 팀장 이중 검토 후 실행 |
| **독립 검증** | AI 모델·로직을 개발팀과 독립된 부서(컴플, 리스크)가 검증 |
| **출처 강제** | 모든 AI 응답에 근거 데이터·출처 명시 의무 |
| **감사 로그** | 입력→처리→출력·승인·실행 전 과정 100% 기록, 5년 보존 |
| **사전 승인** | 유형 3·4 적용 시 AX팀장 + IT업무개발팀장 사전 승인 |
| **환각 검증** | LLM-judge로 신뢰점수 산출, 90% 미만 시 사람 검토 강제 |
| **비상 중단** | 에이전트 오작동 즉시 중단 Circuit Breaker 구현 의무 |

### 2-3. 승격 기준 (고위험 과제 파일럿→운영)

| 단계 | 기준 | 승인자 |
|------|------|-------|
| PoC (2주) | 기술 실현 가능성 + 데이터 가용성 확인 | AX팀장 + 컴플라이언스 |
| 파일럿 (8주) | KPI 80% 이상 + 사고 0건 + 독립 검증 완료 | IT업무개발팀장 |
| 운영 승격 | KPI 90% 이상 + 감사 로그 완비 + 컴플 최종 승인 | IT업무개발팀장 + 준법감시인 |

## 3. 중위험 업무 통제 요건

### 3-1. 적용 업무

| 업무 분류 | 세부 업무 |
|---------|---------|
| 고객 상담·안내 | 챗봇 응답, FAQ 자동화, 상품 일반 안내 |
| 내부 리포트 자동화 | 운용 일일 보고서 초안, 시장 브리핑, 주간 요약 |
| 문서 분류·요약 | DMS 문서 분류, 계약서 요약 검토 지원, 규정집 Q&A |
| 마케팅·데이터 분석 | 고객 세분화 분석, 캠페인 성과 리포트 |
| 업무 효율화 APA | 공시 자동 분류, 데이터 정합성 체크, 알림 자동화 |

### 3-2. 필수 통제 요건

| 통제 항목 | 요건 |
|---------|------|
| **사람 검토 후 확정** | AI 산출물은 초안. 담당자가 검토 후 최종 확정 |
| **출처 명시** | 사실 주장 시 근거 출처 포함, 불확실한 경우 "확인 필요" 표시 |
| **환각 검증** | 신뢰점수 70% 미만 시 "검증 필요" 경고 표시 |
| **분기별 KPI 점검** | 정확도·사용률·오류율 분기 점검, AX팀 보고 |
| **과제 등록 의무** | 유형 2 이상 → AX팀 과제 등록 후 운영 |

### 3-3. 승격 기준 (중위험 과제 파일럿→운영)

| 단계 | 기간 | 기준 | 승인자 |
|------|------|------|-------|
| PoC | 2주 | 기술 실현 가능성 확인 | AX팀장 |
| 파일럿 | 4~6주 | KPI 60% 이상 + 현업 사용률 유지 | AX팀장 + 현업 부서장 |
| 운영 승격 | — | KPI 80% 이상 + 사고 0건 | IT업무개발팀장 |

## 4. 저위험 업무 통제 요건

### 4-1. 적용 업무

| 업무 분류 | 세부 업무 |
|---------|---------|
| 내부 생산성 | 코드 어시스턴트, 문서 교정, 번역, 이메일 초안 |
| 교육·연구 | 학습 자료 작성, 논문 요약, 아이디어 탐색 |
| 행정 지원 | 스케줄 관리, 내부 검색, 회의록 초안, 템플릿 생성 |

### 4-2. 기본 통제 요건

| 통제 항목 | 요건 |
|---------|------|
| **데이터 제한** | G1 데이터만 사용 (내부제한·기밀 입력 금지) |
| **사람 검토 권장** | 생성물 사용 전 검토 (의무 아님, 권장) |
| **개인 계정 사용 시** | G1 업무만, 사내 데이터 절대 입력 금지 |

저위험 업무는 AX팀 과제 등록 없이 유형 1(AI 서비스 활용) 수준에서 자유 사용 가능하다.

## 5. 위험등급별 요약 비교

| 구분 | 고위험 | 중위험 | 저위험 |
|------|-------|-------|-------|
| Human-in-the-loop | 필수 (이중 승인) | 권장 (사람 검토 후 확정) | 선택 |
| 과제 등록 | 필수 | 유형 2 이상 시 필수 | 불필요 |
| 독립 검증 | 필수 | 분기 KPI 점검 | 없음 |
| 감사 로그 보존 | 5년 | 1년 | 없음 |
| 환각 검증 기준 | 90% 미만 → 차단 | 70% 미만 → 경고 | 없음 |
| 파일럿 기간 | 8주 | 4~6주 | — |
| 운영 승인자 | IT팀장 + 준법감시인 | IT업무개발팀장 | — |
| 최대 유형 | 유형 4 (임원 사전 승인) | 유형 4 | 유형 1 권장 |

## 6. 위험등급 재평가 기준

다음 상황 발생 시 즉시 위험등급을 재평가한다.

- AI 시스템이 실제 오류를 발생시켜 고객·업무 영향이 확인된 경우
- 적용 업무 범위가 최초 등록 시보다 확대된 경우
- 기밀등급이 높은 데이터를 새로 처리하게 된 경우
- 관련 법령·감독지침이 개정된 경우
- 연간 정기 재평가 (매년 1월)
