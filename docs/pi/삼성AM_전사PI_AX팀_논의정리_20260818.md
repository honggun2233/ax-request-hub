# 삼성자산운용 전사 PI 추진 — AX팀 논의 정리
**일자**: 2026-08-18

---

## 1. 논의 배경 및 재정의

- 처음엔 "PI팀이 별도로 있고 AX팀이 지원"하는 구조로 오해했으나, 실제로는 **PI팀이 따로 없고 AX팀이 전사 PI를 직접 주관**해야 하는 구조로 재정의됨
- AX팀은 "AI 기술 지원팀"이 아니라 **전사 프로세스 오너(주관 조직)**로 역할 확장

---

## 2. 전사 PI 추진 체계 — 4가지 축

| 축 | 내용 |
|---|---|
| ① 진단 체계 | 전사 업무 프로세스 발굴·병목 진단 |
| ② 우선순위 엔진 | 임팩트×실현가능성으로 과제 랭킹 |
| ③ 실행 파이프라인 | 발의→기획→구현 표준 절차 (기존 SDLC Phase 0~4 재사용) |
| ④ 거버넌스 | 과제 승인·추적·성과측정 체계 |

### 발굴 퍼널 구조
```
전사 부서 인터뷰/설문 (분기 1회)
      ↓
    후보 풀 (제약 없이 수집)
      ↓
  스코어링 (임팩트 × 실현가능성 × 데이터 준비도)
      ↓
   Phase 0 발의서 (AX팀 작성)
      ↓
   상위 3~5개 파일럿 착수
```

### 진단 체계: 2단계 하이브리드
| 단계 | 방식 | 대상 | 목적 |
|---|---|---|---|
| 1차 스크리닝 | 설문(정량) | 전 부서 담당자/팀장 | 넓게, 빠르게 후보 수집 |
| 2차 정밀진단 | 인터뷰(정성) | 1차 상위 후보군만 | 실현가능성·데이터 준비도 확인 |

**설문 문항(5개, 안)**: 반복빈도 / 병목단계 / 데이터 형태 / 규칙기반 vs 판단기반 / 자유서술

**전체 소요기간**: 설문 2주 + 인터뷰 2주 + 스코어링 1주 = 약 5주

**미결정 사항**: AX Request Hub(포트 3005)에 진단 모듈을 붙여 데이터 축적까지 겸용할지, 별도 툴(구글폼 등)로 빠르게 시작할지 → 아직 미확정

## 4. 킬러 아이템: 문서관리 체계화

### 왜 문서관리부터인가
- 전사 직원의 **불만·민원 다수**, 현재 사용 중인 **사이버다임 DESTINY ECM의 신뢰도 저하 + 유지보수 부실**
- "설득해서 시작하는 PI"가 아니라 **"이미 불만이 쌓인 곳에 대안을 들고 가는 PI"** — PI 착수 조건상 최적

### 직접효과 vs 파급효과
**직접효과**: 검색시간 단축, 중복/오류 제거, 컴플라이언스 대응, 컨설팅비 절감

**파급효과(더 중요)**: 문서정리 인프라가 없으면 아래 후속 PI 과제들이 전부 막힘
- 결재/품의 AI 사전검토
- 부서간 리포팅 자동화
- 계약 리스크 자동 플래깅
- 사내 AI 챗봇/Q&A (RAG)
- 신입 온보딩 자동화

→ **문서관리는 PI 과제 하나가 아니라, 다른 모든 PI 과제의 실행 가능성을 좌우하는 인프라**

### 컨설팅 vs AI 내재화 비교
| 항목 | 컨설팅 방식 | AX팀 내재화 |
|---|---|---|
| 비용 | 5~15억 (+SI 별도) | 3,000만~9,000만 원(전사 확산 기준) |
| 절감률 | 기준 | 약 85~95% |
| 기간 | 6~12개월 | 파일럿 6주 + 확산 3~6개월 |
| 지속성 | 1회성 스냅샷 | 신규문서 자동처리 지속 |
| 역량 | 외부 의존 | AX팀 내재화 |

**파일럿(도메인 1개, 4~6주) 예상 직접비용**: 약 300만~1,000만 원 (API+소규모 인프라)

⚠️ 위 수치는 API·인프라 직접비용만 반영한 추정치이며, 파일럿 실측 후 재조정 필요. 법무/보안 승인·조직 저항 대응 시간은 미반영.

### 솔루션 vs AI의 관계 — "머리와 몸통"
- AI가 문서관리 솔루션을 **대체하지 않음**. AI는 지능형 레이어(분류·검색·요약), 그 아래 저장·버전관리·권한통제·보존정책은 여전히 솔루션(또는 자체 구축 인프라) 필요
- 상용 ECM 재도입보다는 **기존 DMS 기획 프로젝트를 인프라 축으로 삼고, 그 위에 AI 레이어를 얹는 경량 자체구축**을 추천 (기존 아키텍처 원칙: 단계적 확장과 일치)

```
DMS 프로젝트 (인프라: 저장·버전·권한·보존)
      +
PI 파일럿에서 만든 AI 레이어 (분류·태깅·검색·요약)
      =
AI 내재화형 문서관리 시스템
```

## 5. 오너십 문제 — 진짜 병목

### 문제의 본질
- 문서 등급(대외비/극비 등)은 오너 부서만 결정 가능
- 20년치 문서를 부서가 전건 열람해서 판단하는 건 **물리적으로 불가능** → 그래서 지금까지 방치됨

### 해법: "전건 검토"를 "예외 검토"로 전환
- AI가 전건 1차 스캔 + 신뢰도 점수 산출
- 고신뢰도(자동확정) / 중간(배치 승인) / 저신뢰도(개별검토)로 분기
- **오너십은 그대로 부서에 있고, 봐야 할 문서량만 대폭 축소**

```
20년치 비정형 문서 전건
      ↓
AI 1차 스캔 (내용분석 + 메타데이터 + 유사사례 매칭)
      ↓
신뢰도 점수
   ├─ 높음 → 자동 등급 확정 (오너부서 사후 통보)
   ├─ 중간 → 배치 검토 (유형별 일괄승인)
   └─ 낮음 → 개별 검토
      ↓
확정 데이터 → AI 재학습 데이터로 축적 (선순환)
```

### AI 1차 스캔 방법론
3가지 신호 결합 (LLM 단독 판단 X):
| 신호 | 내용 |
|---|---|
| 내용 분석 | LLM이 텍스트에서 주제·민감정보 추출 |
| 메타데이터 | 발신부서·작성일·문서유형·수신범위 |
| 유사사례 매칭 | 임베딩 벡터로 과거 확정 문서와 유사도 비교 |

**Seed Data가 선결과제**: 오너 부서가 "최근 1~2년, 100~200건만" 먼저 등급 확정 → 이 표본으로 AI가 판단기준을 학습 → 나머지 20년치에 확장 적용. "20년치 다 봐달라"가 아니라 "소량만 봐달라"는 요청이 핵심.

### AI의 한계 (명확히 구분)
| AI 가능 | AI 불가능(오너 판단 필수) |
|---|---|
| 과거 패턴 기반 등급 추정 | 등급기준 최초 정의 |
| 유사문서 클러스터링 | 정치적/법적 민감 경계선 케이스 |
| 대량 1차 스크리닝 | 소유권 불명확 문서(조직개편 등) |
| 신뢰도 낮은 건 자동 플래깅 | 최종 책임 소재 |

## 6. 기술적 실현 가능성

- 최신 Claude 모델(Sonnet 5 등)은 최대 100만 토큰 컨텍스트, 다국어(한국어 포함) 처리 기본 지원, 구조화 출력(JSON 등) 가능
- Batch API 사용 시 표준가의 50%로 대량 문서 처리 가능 (20년치 배치 처리에 적합)
- 아키텍처: **LLM(내용판단) + 임베딩모델(유사도매칭) + 벡터DB + 오케스트레이션 로직**의 조합
- **진짜 병목은 모델 성능이 아니라**: ① Seed data 확보, ② 사내 보안정책상 외부 API 전송 가능 여부(폐쇄망/온프레미스 필요성 검토)
